# Support

Tessera uses [GitHub issues](https://github.com/QuinntyneBrown/Tessera/issues)
for project questions, bug reports, and feature requests.

The project is in the design stage and has no released package or dedicated
support service. Responses depend on maintainer availability.

## Project questions

Read the [README](README.md), [documentation](docs/README.md), and existing
issues before opening a question. Describe the goal, relevant requirement or
design, and the part that needs clarification.

General Angular questions belong in the appropriate Angular community channel.
Questions about Tessera's intended behavior belong in this repository.

## Bug reports

Use the bug report template and include:

- A concise description of the problem.
- The affected commit or package version, if applicable.
- Steps to reproduce, expected behavior, and actual behavior.
- Relevant operating system, browser, Angular, and SCORM edition information.
- A minimal reproduction or redistributable fixture.
- Sanitized diagnostic output or screenshots where useful.

For a documentation defect, identify the file and passage. For an accessibility
defect, include the interaction, assistive technology, and platform involved.

Use synthetic learner data. Remove credentials and personal information from
reproductions, logs, and screenshots.

## Feature requests

Describe the user need, proposed behavior, and how success could be verified.
Identify related requirements and any effect on accessibility, runtime
compatibility, or LMS integration.

A proposal does not create a delivery commitment. Maintainers assess it against
the project scope and available capacity.

## Accessibility reports

Use the accessibility report template for keyboard, screen reader, focus,
announcement, or layout issues. Include the platform and steps needed to
observe the problem.

Accessibility defects receive the same acceptance criteria and regression
coverage as other production behavior defects.

## Private reports

For suspected security vulnerabilities, follow [SECURITY.md](SECURITY.md).
For harassment or other conduct concerns, follow
[CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

Do not post sensitive details in public support requests.
