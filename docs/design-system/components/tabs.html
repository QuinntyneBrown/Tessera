Tabs

Tabs switch between views of the same object without leaving the page: a course's overview, lessons, learners and grades. One tab is always selected; arrow keys move between tabs.

Overview

Use tabs when one object has several parallel views and a person needs only one at a time: a course's Overview, Lessons, Learners and Grades. Every tab panel belongs to the same thing; switching never loses input.

  • Underline is the default, for page-level sections of an object.
  • Pill (.tabs--pill) is for compact view switches inside a card or above a list ("All", "In progress", "Completed").
  • With counts (.tabs__count) adds a number when it helps choose a tab ("Learners 24").
  • Scrollable is not a separate class: every tab list scrolls horizontally when it overflows instead of wrapping.

Do not use tabs for steps in a sequence (use a stepper), for navigation between separate pages (use sidebar navigation or links styled with aria-current="page"), or to toggle a setting (use a segmented button group). If a person needs to compare two panels, show both.

Activation: automatic or manual

Both APG activation models are supported; choose per tab list and say which in the spec:

  • Automatic: moving focus with an arrow key selects the tab and shows its panel. Use it when panels render instantly from data already on the page.
  • Manual: arrows move focus only; Enter or Space selects. Use it when showing a panel fetches data or is slow (a Learners panel that loads from the LMS), so arrowing past a tab does not fire a request.

The examples on this page use automatic activation, except the one labelled "Manual activation" under Variants.

Anatomy

  1. Tab.tabs__tab: a <button role="tab">, 44px tall, 16px inline padding, --text-label.
  2. Selection indicator2px --color-accent bottom border plus accent text on the selected tab. Pill: an accent fill.
  3. Count (optional).tabs__count: a 12px pill on --color-bg-subtle; part of the tab's name.
  4. Tab list.tabs__list: role="tablist" with a label, 1px --color-border-default baseline, scrolls horizontally on overflow.
  5. Panel.tabs__panel: role="tabpanel", labelled by its tab, 16px block padding, tabindex="0" when it has no focusable content.

Sizes

Medium (44px) is the default and the comfortable touch target. Small (32px, .tabs--sm) is for pill filters inside dense cards and popovers; it still exceeds the 24px minimum.

Heights: --control-height-sm/md; inline padding: --space-3 (sm), --space-4 (md); font --text-label in both.

Both themes

  • Selected (aria-selected="true"): accent text and a 2px accent bottom border (underline) or an accent fill (pill). Weight does not change, so tabs never shift width when selected.
  • Disabled (aria-disabled="true"): readable --color-fg-disabled text with a dashed line-through. The tab stays focusable with arrow keys, so a person can find it, but it cannot be selected. Explain why near the tab list ("Grades are available after the first assessment").
  • Active has no separate look; selection is immediate.
  • Focus draws the amber ring inset by its own width so the scrolling tab list never clips it.

Responsive behaviour

  • The tab list never wraps. When tabs overflow (at 320px, at 400% zoom, with 200% text or with text-spacing overrides) .tabs__list scrolls horizontally inside itself with a thin scrollbar; the page never scrolls sideways.
  • Arrow-key focus scrolls the focused tab into view; selecting a tab with the pointer scrolls it fully into view.
  • Tab labels never truncate. If a list overflows at 768px with default text, there are too many tabs or the labels are too long: shorten them or move to a select or sidebar.
  • Panels are full width at every breakpoint; their content follows its own layout rules.

Theming

Tabs read semantic tokens directly: --color-fg-muted (unselected label), --color-fg-accent + --color-accent (selected), --color-bg-subtle (hover and count), --color-border-default (baseline), --color-border-strong (pill edge), --color-fg-on-accent (selected pill label) and --color-fg-disabled. There are no component tokens; scope semantic tokens to re-skin a tab list.

/* Tabs on a sunken toolbar keep their counts visible */
.course-toolbar .tabs { --color-bg-subtle: var(--color-bg-surface); }

In the dark theme the accent lightens to teal-300 and the pill label flips to sage-900, keeping the selected pill above 8:1. In the shipped packages the selected colour is --t-colorBrandForeground1 and the underline --t-colorBrandStroke1; see theming.

Accessibility

Role and pattern

The WAI-ARIA APG Tabs pattern: a role="tablist" container with an accessible name, <button role="tab"> children with aria-selected and aria-controls, and role="tabpanel" panels with aria-labelledby pointing back at their tab. Roving tabindex: the selected tab has tabindex="0", all others -1. Activation is automatic or manual per tab list (see Overview); the examples use automatic, except "Manual activation".

Keyboard

KeyAction
TabInto the tab list: focuses the selected tab. From a tab: moves to the panel (or the first focusable element in it).
Shift+TabFrom the panel back to the selected tab; from a tab out of the list.
→ / ←Next / previous tab, wrapping at the ends. Automatic: also selects it. Manual: focus only. In right-to-left layouts the keys mirror.
Home / EndFirst / last tab (selecting it in automatic mode).
Enter, SpaceManual mode: selects the focused tab. Has no effect on a disabled tab.

Focus

The shared 3px amber ring, drawn inside the tab (negative offset) so the overflow container never clips it. Selecting a tab does not move focus into the panel; the person presses Tab. Panels without focusable content take tabindex="0" so they can be reached and read.

Labelling

The tab list is named after the object ("Course: Better conversations at work"). Each tab's text is its name; counts are part of it ("Overdue 3"). Screen readers announce "Overdue 3, tab, selected, 2 of 3". Panels are named by their tab. Disabled tabs are announced as "dimmed" or "unavailable"; put the reason in text near the list and reference it with aria-describedby on the disabled tab.

Motion

Selection changes instantly; the underline does not slide. Panels swap without a transition. Scrolling a focused tab into view uses behavior: "smooth" only when prefers-reduced-motion is not set.

Touch

Medium tabs are 44px tall; small tabs are 32px with 4px (underline) or 8px (pill) between them, above the 24px minimum. The scrollable list can be swiped. Hover only applies under (hover: hover).

Content

  • Tab labels are one or two nouns in sentence case: "Overview", "Learners", "Completion rules". No verbs, no "View…".
  • Keep a tab list to two to six tabs. One tab is not a tab list; seven or more needs another pattern.
  • Counts are plain numbers, up to "99+"; omit the count rather than show "0" unless zero is the point ("Overdue 0").
  • Order tabs by importance, Overview first. Do not reorder tabs at run time.
  • Say why a tab is disabled, in a sentence near the list.

<script>
  // Automatic activation; for manual, select on Enter/Space instead of on arrow.
  tablist.addEventListener('keydown', (event) => {
    const tabs = [...tablist.querySelectorAll('[role="tab"]')];
    const i = tabs.indexOf(document.activeElement);
    const next = { ArrowRight: i + 1, ArrowLeft: i - 1, Home: 0, End: tabs.length - 1 }[event.key];
    if (next === undefined) return;
    event.preventDefault();
    const tab = tabs[(next + tabs.length) % tabs.length];
    tab.focus();
    if (tab.getAttribute('aria-disabled') !== 'true') select(tab);
  });
</script>
