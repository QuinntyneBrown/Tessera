Progress bar

A progress bar shows how much of something is done: lessons completed in a course, files uploaded in a SCORM package, learners imported. It always comes with a label that says what is progressing and a value in words.

Overview

Use a progress bar when the amount of work is known or can be estimated, and when it takes long enough (more than about 2 seconds) or matters enough (course completion) to show.

  • Determinate: a known fraction. Course progress ("2 of 5 lessons"), package upload ("14 of 32 MB").
  • Indeterminate: work is happening but its size is unknown, and the region it belongs to is wide enough for a bar (loading a SCORM package manifest).
  • Success / danger: the finished outcome, held for a moment or kept on summaries ("Course complete", "Import failed at 60%").

Use a spinner for short, unknown waits in small spaces (a field, a button); a skeleton while a layout's content loads; a stepper when the steps themselves need names and navigation, as in the SCORM course outline.

Anatomy

  1. Label--text-body-sm, default colour. Names what is progressing; it is the bar's accessible name via aria-labelledby.
  2. Value.progress__value, muted, tabular numbers. In units people count ("2 of 5 lessons"), not only a percentage. Mirrors aria-valuetext.
  3. Track8px tall, full radius, 1px --color-border-strong edge so the empty part is visible (3:1).
  4. BarAccent fill, width from --progress; animates over --duration-deliberate.

Outcome is said in words ("Complete", "Stopped at"); the colour only supports it.

Sizes

One size: an 8px track. Emphasis comes from placement and label, not a thicker bar.

States

A progress bar is not interactive, so hover, focus, active and disabled do not apply. Its states are values. If a bar sits inside something clickable (a course card), that container owns the pointer and focus states.

  • Updating: the bar animates to the new width; the visible value updates at once. Do not announce every step; announce milestones (lesson complete, upload finished) in a polite live region, as the SCORM player does with "Start with listening complete."
  • Complete: switch to .progress--success and say "Complete" in the value. On the SCORM course header, completion also appears in the course status list.
  • Failed: switch to .progress--danger, freeze the bar at the point reached, and explain under it with an inline message or an alert.

Responsive behaviour

  • The bar fills its container's width; it has no minimum width beyond its label.
  • The header is a flex row with a gap: when label and value no longer fit on one line (long file names, 400% zoom), the label wraps first; the value never truncates.
  • Track height is fixed at 8px (0.5rem, so it scales with root font size) and does not change between breakpoints.
  • In the SCORM course header the bar sits under the course title on every width; on phones it stays full width above the player.

Theming

The bar reads --color-accent (fill), --color-bg-surface (track), --color-border-strong (track edge), --color-success-solid and --color-danger-solid (outcomes), and --color-fg-muted (value). The fill width is the only component property, --progress, set per instance. In the dark theme the accent becomes teal-300 on a sage-900 track, which keeps the fill well above 3:1. In the shipped SCORM package the fill maps to --t-colorBrandBackground; see theming.

/* A course card with a quieter bar */
.course-card .progress__bar { background: var(--color-fg-accent); }

Accessibility

Role and pattern

role="progressbar" on the track with aria-valuemin, aria-valuemax, aria-valuenow and a human aria-valuetext ("2 of 5 lessons"). Indeterminate bars omit aria-valuenow; the region they describe sets aria-busy="true" while loading. See the APG Meter pattern for the distinction: a progress bar is for task progress; a static measurement (quiz score) is a meter.

Keyboard

KeyAction
(none)Not focusable and has no keyboard interaction. The value is reachable in browse mode and as visible text. A Cancel button for a long task sits next to the bar.

Focus

Never focusable. When a long task finishes, focus is not moved; a polite announcement reports the result.

Labelling

The visible label is the accessible name (aria-labelledby); the visible value equals aria-valuetext. Milestones are announced through the page's polite live region, not by the progress bar itself, so screen readers do not read every percentage change.

Contrast

Fill on track
Track edge on surface
Success fill on track
Danger fill on track
Value text on surface

Motion

Width changes animate over --duration-deliberate (500 ms). The indeterminate sweep loops over --duration-loop-shimmer. Under prefers-reduced-motion width changes are instant and the indeterminate bar stops and fills the track at half opacity, so it still reads as "in progress" without movement.

Touch

Not a target. Do not make a progress bar a seek control; use a slider for that.

Content

  • Label says what is progressing: "Progress", "Uploading better-conversations.zip", "Importing learners".
  • Value uses the units people count: "2 of 5 lessons", "14 of 32 MB". Add a percentage only when units are meaningless.
  • Indeterminate labels describe the activity with an ellipsis: "Checking the course package…".
  • Outcomes in words: "Complete", "Stopped at 120 of 200". Never rely on the bar turning green or red.
  • Do not estimate time remaining unless it is reliable; a wrong estimate is worse than none.
