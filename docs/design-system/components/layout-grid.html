Container, grid and stack

Seven layout primitives place every Tessera screen: a centred container, a 4/8/12-column grid, an auto-filling card grid, vertical stacks, wrapping clusters, the SCORM player's wrapping sidebar layout, and the page header. They read the layout tokens, so margins, gutters and columns change in one place.

Overview

Compose pages from these primitives instead of writing one-off flex and grid rules. They carry no colour and no semantics; put landmarks and headings on the elements inside them.

  • .container: caps content at --layout-container-max (90rem / 1440px, the SCORM and video shells) and adds --layout-margin on both sides.
  • .grid: --layout-columns equal columns (4 on phones, 8 from 768px, 12 from 1024px) with --layout-gutter gaps. Children span with grid-column; .span-full spans all.
  • .grid--auto: as many 18rem columns as fit, for card catalogues.
  • .stack: vertical flow with one gap (--stack-gap, default 16px).
  • .cluster: a wrapping row (--cluster-gap, default 12px) for buttons, badges, metadata.
  • .sidebar-layout: side panel plus main panel that wraps without a media query. The side column stacks above the main one as soon as the main cannot keep 30rem, so enlarged text never squeezes the player.
  • .page-header: eyebrow, title, lead and an optional action that wraps below the title.

Page-level shells (top bar, side navigation) are documented on the layout foundation and the top bar and sidebar navigation pages.

Anatomy

  1. Margin--layout-margin: viewport edge to content. 16px, 24px from 768px, 32px from 1024px.
  2. Columnrepeat(var(--layout-columns), minmax(0, 1fr)): 4, 8 or 12 equal tracks that never overflow.
  3. Gutter--layout-gutter: space between columns. 16px, then 24px from 768px.
  4. Container edge--layout-container-max (90rem); beyond it the margins grow and content stays centred.

Sizes

The primitives' "sizes" are their gaps. Choose by relationship: tight for parts of one thing, wide for separate things.

--stack-gap / --cluster-gap: --space-2 label to field, --space-4 default, --space-6 between panels (the mocks' 1.5rem layout gap), --space-8 between page sections.

States

Layout primitives are not interactive and have no states; their behaviour changes with viewport width, documented under Responsive.

Responsive behaviour

RangeColumnsGutterMarginTypical
0 – 767px4--space-4 (16px)--space-4 (16px)Phones; everything one column; sidebar layout stacked.
768px (--layout-breakpoint-md)8--space-6 (24px)--space-6 (24px)Tablets; two-up cards; outline toggle hidden.
1024px (--layout-breakpoint-lg)12--space-6 (24px)--space-8 (32px)Laptops; outline beside player.
1440px (--layout-breakpoint-2xl)12--space-6autoContent stops at --layout-container-max.
  • Breakpoints are min-width queries in rem (48rem, 64rem), so they follow the reader's font size. Custom properties cannot be used in @media; the values are repeated by convention.
  • .sidebar-layout and .grid--auto are intrinsic: they respond to the space they have, not the viewport, so they also work inside a narrow LMS frame and at 400% zoom.
  • Every track is minmax(0, 1fr) and every flex child min-width: 0, so long words wrap instead of forcing horizontal scroll at 320px.
  • .page-header wraps its action below the title when they do not fit; the title drops from --font-size-4xl to --font-size-3xl below 768px.
  • Vertical rhythm never scales with viewport width; the token changes at a breakpoint instead.

Theming

The primitives draw nothing, so they look the same in every theme. Hosts re-theme layout by overriding layout tokens on a container, not by editing the classes.

/* An LMS embeds Tessera in a narrow content column */
.host-lesson-frame { --layout-container-max: 60rem; --layout-margin: var(--space-4); }
/* A denser catalogue */
.host-catalogue .grid { --layout-gutter: var(--space-4); }

Accessibility

Role and pattern

No role: these are presentational containers. Use landmarks inside them (<main>, <nav aria-labelledby> for the outline, <section aria-labelledby> for the player, <aside> for notes). The primitives exist to meet WCAG 1.4.10 Reflow and 1.4.12 Text Spacing.

Keyboard

KeyAction
Tab / Shift+TabFollows DOM order, which is the visual order at every width. Never reorder with order, flex-direction: row-reverse or explicit grid placement that changes reading order.

Focus

Containers are not focusable. Leave room for focus rings: overflow: hidden on a layout wrapper clips the 5px ring of anything at its edge, so only clip media.

Labelling

Name the landmarks inside, not the layout. In the sidebar layout the outline comes first in the DOM, so screen reader and keyboard users meet the outline before the player, matching the stacked order on phones.

Motion

Layout changes are never animated; panels jump to their new place on resize.

Touch

Gutters of at least 16px keep targets in neighbouring columns apart. Fixed bottom bars add env(safe-area-inset-bottom); full-height layouts use 100dvh.

Content

  • Prose stays within --layout-measure (60ch) even inside wide columns; the page header lead and the video intro already do.
  • Put the most important panel first in the DOM when the order is a choice; it is first on phones.
  • Page header eyebrows are one or two words ("Course", "Component design reference"); titles are the page's subject.

Drift fixed during extraction:

  • Shell padding was 2rem 1.5rem 3rem (SCORM, video), 2rem 1.5rem 4rem (combobox), and on phones 1.3rem 1rem 2rem and 1.25rem 0.75rem 3rem; replaced by --layout-margin inline and --space-8 / --space-12 block.
  • Containers were 1440px and 72rem; the system container is --layout-container-max (90rem); 72rem is kept only for these docs.
  • Breakpoints 40em and 47.5em written as max-width; now --layout-breakpoint-sm (40rem) and --layout-breakpoint-md (48rem), min-width first.
  • The narrow-screen layout gap was 1rem in the SCORM mock; the gutter token handles it (16px below 768px).
  • The sidebar basis stays 15.5rem from the mock; --layout-sidebar-width (16rem) is for page navigation, not this layout.
