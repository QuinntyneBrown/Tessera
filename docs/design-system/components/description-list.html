Component · Data display

Description list

Description lists show the facts about one thing as term and value pairs: a course's completion and save status, a live session's presenter and start time, a learner's enrolment details.

WCAG 2.2 AAStatus: stableNative <dl>

Overview

Use a description list for the attributes of a single record, where each value only makes sense next to its term. Use a table to compare the same attributes across many records and a list for a set of similar items.

  • Horizontal (.dl): terms in a column on the left, values beside them. For detail panels with four or more pairs ("Learner details").
  • Vertical (.dl--vertical): each term above its value. For narrow side panels and long values.
  • Inline (.dl--inline): pairs flow in a wrapping row under a heading. This is the metadata row both mocks use: SCORM "Completion: Unknown · Save status: Last saved at 10:42" and video "Session · Started · Presenter".

Anatomy

  1. Term<dt>: bold (--font-weight-bold) in --color-fg-default, --text-body-sm. No trailing colon.
  2. Value<dd>: --color-fg-muted, no indent. May hold text, a badge, a link or an avatar with a name.
  3. GapsGrid: --space-2 between rows, --space-6 between term and value columns. Inline: --space-1 inside a pair, --space-6 between pairs.

Sizes

One size. The list inherits --text-body-sm; it scales with the user's text size and never has its own size modifiers.

States

The list itself is not interactive. Its states are the states of its values, and of any link a value holds (forced here with data-state).

  • Empty value: an en dash "–" with a visually hidden reason, or words when the reason matters ("Unknown", "Not available yet"). Never leave a <dd> blank; the term would be read with nothing after it.
  • Loading: a skeleton in the value, the term stays real. aria-busy="true" on the <dl>.
  • Updated: a value that changes while the page is open (SCORM "Save status") is announced through a polite live region the first time it appears and whenever it recovers from "Not saved"; an unchanged value is never re-announced. The SCORM mock hides the whole pair until the first save.
  • Disabled, active, selected do not apply: there is nothing to operate.

Responsive behaviour

  • Horizontal stacks into the vertical form below 40rem (--layout-breakpoint-sm), so long terms never squeeze values into a sliver at 320px.
  • Vertical is the same at every width.
  • Inline wraps whole pairs onto new lines (flex-wrap); a pair itself never splits between term and value unless the value alone is wider than the container, in which case the value wraps.
  • Long values (e-mail addresses, course names) wrap; add overflow-wrap: anywhere on values that can contain unbroken strings. Nothing truncates.
  • With 200% text or WCAG text-spacing overrides the grid's term column grows; the stack breakpoint is in rem, so it also moves earlier as text grows.

Theming

The description list reads two semantic tokens: --color-fg-default for terms and --color-fg-muted for values. It has no component tokens. Values that hold components (badges, links, avatars) theme themselves.

/* A summary card that wants values as strong as terms */
.summary-card .dl dd { color: var(--color-fg-default); }

In the dark theme terms become sage-25 and values sage-200, matching the video mock's dark --page-ink and --page-muted. See theming.

Accessibility

Role and pattern

Native <dl>, <dt>, <dd>; no ARIA role is needed and there is no APG widget pattern because nothing is operable. The structure satisfies WCAG 1.3.1 Info and relationships: the term–value relationship is in the markup, not only in the layout. A <div> may wrap each dt/dd group (required for .dl--inline); no other wrapper is allowed. Screen readers vary: NVDA and JAWS announce "description list" or "definition list" with item counts; VoiceOver and TalkBack read terms and values in order. All are acceptable because the order is term, then value.

Keyboard

KeyAction
Tab / Shift+TabReaches links and buttons inside values only. The list, terms and plain values are never focusable.
EnterFollows a link value.

Focus

Only interactive values receive focus, with the shared amber ring. Updating a value never moves focus.

Labelling

The term labels the value; do not repeat it inside the value. When the list follows a heading, that heading names it; no aria-label is needed. Drop the colon the SCORM mock put in its terms ("Completion:"): screen readers read it as part of the term, and the bold term already separates it visually. Values that change live (save status, viewer count) get one polite live region for the whole metadata row, not one per value.

Motion

None. Loading skeletons shimmer and stop under prefers-reduced-motion; updated values change without animation.

Touch

Not interactive. Link values follow the link target rules (at least 24px tall, or inline in text).

Content

  • Terms are short nouns in sentence case: "Completion", "Save status", "Started", "Presenter". No colon, no question form.
  • Values are facts, not sentences: "10:30", "Lecture hall A", "Last saved at 10:42".
  • Times use the 24-hour "10:30" form the mocks use; dates use "31 Oct 2026".
  • Unknown values say so in words: "Unknown", "Not available yet". Use an en dash only where the reason is obvious from context.
  • Keep the same term order on every screen that shows the same record.

Drift fixed during extraction:

  • Two implementations of the same row: SCORM made dt/dd display: inline with a .3rem margin; video used flex <div> pairs with a 0.3rem gap. Unified on .dl--inline with <div> pairs and --space-1.
  • SCORM terms ended with a colon ("Completion:"); video terms did not. Colons removed.
  • Font size 0.9rem in both; normalised to --font-size-sm via --text-body-sm.
  • Row gap .25rem and column gap 1.5rem kept, as --space-1 and --space-6; top margins .5rem / 1rem snapped to --space-2 / --space-4.
  • The horizontal grid and vertical forms are derived: not present in the mocks; they follow the system rules.
