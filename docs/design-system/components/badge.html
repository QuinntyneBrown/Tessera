Component · Data display

Badge

Badges label the state of something in a word or a number: a lesson is "Completed", an assignment is "Overdue", four items are due. They are read, never clicked.

Overview

Use a badge to show a short, stable status or a count next to the thing it describes: in a table status column, at the end of a list item, beside a navigation link. Use a chip when people can select or remove it, an inline message or alert when it needs a sentence, and the video player's LIVE control for live status over media.

  • Neutral: no judgement ("Not started", "Locked", "Draft").
  • Info: in motion ("In progress", "Scheduled").
  • Success: done well ("Completed", "Passed").
  • Warning: needs attention soon ("Due soon", "Not saved").
  • Danger: failed or late ("Overdue", "Failed").
  • Solid: the one badge on a surface that must stand out ("New", "Required"); accent or danger fill.
  • Count: a number with tabular figures ("4"), with its meaning in hidden text.

Status is always colour and text, plus a dot or icon. The colour helps people who see it scan; the word is the status.

Anatomy

  1. Dot or icon (optional).badge__dot: 8px circle in the status icon colour, aria-hidden. Or a 16px .icon--sm (lock, check) when the shape adds meaning.
  2. Label--text-label at --font-size-xs (bold 12px). One or two words in sentence case; never truncated.
  3. ContainerPill (--radius-full), 24px tall (--target-min), --space-2 inline padding, hairline border in the status border colour.

LIVE is a media control, not a badge

The video mock's "LIVE" pill looks like a badge but is a button: aria-disabled at the live edge and "Go to live, n seconds behind" when playback falls behind. It lives in the player's control bar with --color-media-live, which is tuned for the scrim over video. Use the video player's .media-live control there; outside media (a session list saying a lecture is on now) use a danger or info badge with the word "Live".

Sizes

One size: 24px tall (--target-min), bold 12px label. Badges scale with the user's text size; there are no size modifiers.

States

Badges are not interactive, so hover, focus, active and disabled do not apply: if people need to press it, it is a filter chip or a button. A badge inside a link or row inherits that element's hover and focus; the badge itself does not change. The matrix shows every variant in every form it takes.

Changing status

When a status changes while the page is open (a lesson becomes "Completed" in the SCORM player), the badge text updates and the change is announced once through the component's polite live region ("Ask better questions complete."). The badge itself is not a live region; an unchanged status is never re-announced.

Responsive behaviour

  • Badges never wrap or truncate (white-space: nowrap); keep labels to one or two words so they fit at 320px.
  • In a list or table row that runs out of room, the badge moves below the title rather than squeezing it; place it in .list__meta on narrow layouts.
  • Badges are sized in rem and grow with 200% text; the 24px minimum height becomes a minimum, not a fixed height.

Theming

Four component tokens, set by each variant: --badge-bg, --badge-fg, --badge-border, --badge-dot. Each aliases the status set (--color-<status>-bg, -fg, -border, -icon), so a theme that changes the status colours re-skins every badge.

/* A host that wants borderless badges in a dense report */
.report .badge { --badge-border: transparent; }

In the dark theme each status background becomes a deep tint and its text a light tint of the same hue, keeping 4.5:1. The shipped @tessera/theme has no status palette yet beyond --t-colorPaletteRedForeground1 (danger text); see theming and color.

Accessibility

Role and pattern

A plain <span>: no role, no widget pattern, read as text in place. The label is the status; the dot and icon are aria-hidden. This satisfies WCAG 1.4.1 Use of color because the word carries the meaning.

Keyboard

KeyAction
TabNone. Badges are never focusable; never add tabindex to make a status "discoverable". The element it describes is the stop.

Focus

Not focusable. A badge inside a focused link or button sits inside that element's ring.

Labelling

Counts carry their meaning in visually hidden text ("4 due this week") and hide the bare number (aria-hidden), so a screen reader says "Assignments, 4 due this week", not "Assignments 4". Do not use aria-label on the badge span: ARIA prohibits naming a generic element, and several screen readers ignore it. Put the badge after the name it qualifies, so it is read in that order.

The label is 12px bold, so it needs the full 4.5:1. Dots are redundant with the label and are shown at 3:1 as a quality bar, not a requirement.

Motion

None. Badges do not pulse or blink; the pulsing dot belongs to the video player's LIVE control and stops under prefers-reduced-motion.

Touch

Not a target. The 24px height is for legibility, and so that a badge in a row never makes the row's own target smaller.

Content

  • One or two words, sentence case: "Completed", "In progress", "Due soon". Never all caps, never a sentence.
  • Use the shared vocabulary: "Not started", "In progress", "Completed", "Overdue" for learner progress; "Locked" for unavailable lessons; "Live", "Scheduled", "Ended" for sessions.
  • Past tense or adjectives for states ("Completed", "Locked"), not verbs ("Complete it").
  • Counts are numerals; cap the visible number at "99+".
  • Pair "Locked" with the unlock condition in text next to it: "Locked until “Give useful feedback” is complete."

Sources

Extracted from these mocks:

  • scorm-player: lesson states in the course outline ("Complete", "Not reported", "Locked until … is complete") and the filled check on completed lesson numbers; "Not saved" save status.
  • video-player: the LIVE pill, documented here as a media control that is not a badge (see video player).

Drift fixed during extraction:

  • The SCORM outline wrote status as plain muted text at 0.76rem; status words now use badges at --font-size-xs bold, or plain .list__meta text where a badge would be noise.
  • SCORM "Complete" and the system's table vocabulary "Completed" disagreed; badges use "Completed" (a state), the SCORM runtime value stays "complete" internally.
  • Completed lesson numbers were white on accent (color: white); the solid badge uses --color-fg-on-accent, which also passes in the dark theme.
  • The video LIVE dot #ff6b57 failed 3:1 over a white frame (2.79:1); fixed in --color-media-live, which badges do not use.
  • Video pills used 999px; badges use --radius-full.
