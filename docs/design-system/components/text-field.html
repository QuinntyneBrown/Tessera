Text field

A single-line input for short free text: a course title, a learner's email, a passing score, a search term. It always sits in a form field with a visible label.

WCAG 2.2 AAStatus: stableNative <input>

Overview

Use a text field when the answer is short, free-form and fits on one line. Pick the input type for the data, because it sets the mobile keyboard, autofill and validation:

  • Text for names, titles and codes. Codes made of digits ("0042") are text with inputmode="numeric", not numbers.
  • Email (type="email", autocomplete="email") for learner and instructor addresses.
  • Password with a show toggle, so people can check what they typed.
  • Number only for real quantities you might add or compare: passing score, seat count, duration.
  • Search with a leading magnifier addon, for filtering a course catalogue or learner list.

Use a textarea when the answer may run to several lines, a select when the answer is one of a short known list, and a combobox when people search a long or remote list (assigning learners).

Anatomy

  1. LabelFrom the form field: <label for>, bold 16px, always visible.
  2. Value (or placeholder)16px --text-body, --color-fg-default; placeholder in --color-fg-subtle. 16px also stops iOS zooming on focus.
  3. Addon (optional).input-group__addon: unit, prefix or icon, 14px --color-fg-muted, 12px inline padding. Never interactive; a button goes in the group instead.
  4. Container44px tall (--control-height-md), 1px --color-border-strong, --radius-md, 8px × 12px padding, --color-bg-surface.

Sizes

Medium (44px) is the default and the only size for forms. Small fits dense surfaces where a row is already a target, such as a table filter; large is for a single prominent search on a catalogue landing page.

Heights --control-height-sm/md/lg; text --text-body-sm / --text-body / --text-body-lg. Label, hint and error do not change with size.

States

Hover darkens the border to --color-fg-default; focus adds the amber ring (on the group when there is one); invalid thickens the border to 2px --color-danger-solid; disabled drops the fill and dashes the edge; read-only sinks the fill. Pointer and focus states are forced with data-state. Each matrix input is labelled with aria-label here only to keep the table compact.

Both themes

Enter a score from 0 to 100.

Enter a score from 0 to 100.

  • Invalid is never border colour alone: the form field adds the icon and message, and the border also gets thicker (1px to 2px), which reads without colour.
  • Disabled keeps the value readable (--color-fg-disabled passes 4.5:1) and dashes the edge. Disabled inputs are skipped by Tab and not submitted; prefer read-only when the value still matters.
  • Read-only stays focusable, selectable and announced as read-only; the sunken fill and quiet border say "not editable" without looking broken.
  • Required has no visual of its own on the control; the label says "(required)" and the input carries required.

Responsive behaviour

  • The input fills its field (width: 100%, min-width: 0), so it never forces horizontal scroll at 320px. A max-width on the field may hint at expected length (a score, a code); it never sets a minimum.
  • Addons keep white-space: nowrap, so keep them short ("min", "%", "SAFE-"). At 200% text the input part shrinks first; the value scrolls inside the input, which is native behaviour.
  • Value text is 16px at every viewport so mobile browsers do not zoom on focus; the small size (14px) is for pointer-first dense surfaces only.
  • On touch keyboards the type and inputmode pick the layout: email shows "@", numeric shows digits, search shows a search key.

Theming

The input reads four component tokens declared on .input, .textarea and .select: --field-bg (--color-bg-surface), --field-fg (--color-fg-default), --field-border (--color-border-strong) and --field-height (--control-height-md). States override those tokens, so a re-skin survives every state.

/* A host embeds the field on a sunken panel and wants a raised input */
.grading-panel .input { --field-bg: var(--color-bg-surface-raised); }

In dark the surface becomes sage-900, the border lightens to --palette-sage-300 and placeholder text to sage-200, keeping the 3:1 border and 4.5:1 placeholder targets. In the shipped packages these map to --t-colorNeutralBackground1, --t-colorNeutralForeground1, --t-colorNeutralStrokeAccessible and --t-colorStrokeFocus2 (the combobox field's --t-combobox-surface, --t-combobox-text, --t-combobox-border, --t-combobox-focus-ring). See theming.

Accessibility

Role and pattern

Native <input>; its role (textbox, searchbox, spinbutton) comes from type. No ARIA role is added. Labelling and errors follow the labels or instructions and error identification criteria; the show-password control is an APG toggle button. Personal-data inputs set autocomplete (identify input purpose).

Keyboard

KeyAction
Tab / Shift+TabMoves into and out of the input, then to the show-password button. Disabled inputs are skipped; read-only inputs are not.
Typing, Home / End, arrowsNative text editing. Nothing is intercepted.
↑ / ↓Number inputs only: step the value by step, clamped to min and max.
EscSearch inputs: clears the term (native). Other inputs: no effect.
EnterSubmits the enclosing form. Search runs the search.
Space / Enter on the eye buttonToggles the password between hidden and shown; focus stays on the button.

Focus

A plain input shows the shared ring (3px --color-focus-ring, 2px offset) on :focus-visible. In an .input-group the ring moves to the group with :focus-within, as the combobox mock draws it on the field, so addons and the eye button sit inside one ring. The eye button then shows its own ring when it has focus.

Labelling

  • Every input has a visible <label for>; the placeholder is never the name.
  • Units and prefixes that change the meaning of the value ("minutes", "SAFE-") are linked with aria-describedby. Decorative icons are aria-hidden="true".
  • The show-password button is named "Show password" in both states; aria-pressed announces "pressed" when the password is visible. Its name never flips to "Hide".
  • The counter is in aria-describedby; a visually hidden polite live region announces the remaining count only when 10 or fewer characters remain, debounced, not on every keystroke.

The read-only border (--color-border-default) is deliberately below 3:1: a read-only value is not an operable control, and its label and value identify it.

Motion

Only the border colour transitions, over --duration-fast; under prefers-reduced-motion it changes instantly. The focus ring never animates.

Touch

Medium (44px) and large (48px) meet the comfortable target; the label is also a target. The eye button fills the group's height and is at least 40px square. Small (32px) is only used where the pointer is primary, and still exceeds the 24px minimum. Hover styles apply only under (hover: hover).

Content

  • Labels name the value: "Course title", "Instructor email", "Passing score". Put the unit in a suffix ("%", "minutes"), not in the label.
  • Placeholders show an example of the format, or nothing: "Name or email", "Title or course code". Keep them short enough to fit at 320px.
  • Errors say how to fix the value: "Enter an email address like name@example.edu", "Enter a score from 0 to 100", "Course title must be 60 characters or fewer".
  • Never disable paste or autofill in password and email fields; people rely on password managers.

Sources

Derived: the mocks have no standalone text field; this component follows the system rules and is derived from the combobox field it shares a look with.

  • combobox: the field's 1px #657f73 border on all four sides (4.34:1), 0.5rem radius, surface fill, placeholder "Name or email" in #536763 (6.02:1), focus ring drawn on the field container while the input has focus, invalid border in the error colour, dashed disabled edge.
  • video-player: 44px minimum height for form controls in the "Mock states" panel.

Drift fixed during extraction:

  • Combobox field min-height 2.5rem (40px) beside 44px buttons; unified on --control-height-md (44px).
  • Field padding 0.1875rem / 0.375rem was off-grid; snapped to the 4px scale (--space-2 / --space-3).
  • Invalid state changed only the colour of a 1px border; it now also thickens to --border-width-thick so it reads without colour.
  • Two disabled treatments (light background only vs dashed border); unified on the dashed edge with readable --color-fg-disabled text.
  • Focus outline 2px on the field vs 3px on the page; unified on the 3px ring with the 2px --focus-ring-offset.
