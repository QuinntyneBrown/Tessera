Toast

A toast is a short, non-blocking message about something that just happened: an assignment was saved, three learners were removed, the stream is back live. It appears at the edge of the screen, says one thing, and gets out of the way.

WCAG 2.2 AAStatus: stable≥ 8 s · pauses on hover and focus · errors persist

Overview

Use a toast to confirm an action the person took when the result is not otherwise visible ("Assignment saved"), to offer a short-lived Undo ("3 learners removed"), or to report a background failure that has a retry ("Reminder emails not sent"). Toasts never carry the only copy of important information: anything the person must read later belongs on the page.

  • Use an alert when the condition persists and belongs to a region (progress not saved, stream unavailable).
  • Use an inline message for field validation; never a toast.
  • Use a dialog when the person must decide before continuing.
  • Use the pill toast (.toast--pill) only over media, for a transient, non-interactive status such as the video player's "Back live".

See the notifications pattern for choosing between toast, banner and alert.

Anatomy

  1. Tone stripe4px inline-start edge in the tone's border colour; neutral toasts use --color-border-inverse.
  2. Icon (optional)20px, inverse foreground, aria-hidden. Shape varies by tone.
  3. Title and bodyBold title (.toast__title) plus an optional one-line body, --text-body-sm.
  4. Action (optional)One small outlined button: Undo, Retry or View. Never two.
  5. DismissIcon button "Dismiss notification"; required on every interactive or persistent toast.
  6. ContainerInverse surface, --radius-md, --shadow-3, padding 12 × 16px, inside a .toast-region.

With an action

Undo replaces a confirmation dialog for reversible actions; Retry recovers a background failure. A toast with an action stays at least 10 s, and it never disappears while focus or the pointer is inside it.

Stacked

Toasts stack in one .toast-region, newest at the bottom (nearest the edge), 8px apart, at most three visible; older ones collapse into the queue. In product the region is fixed bottom-right; docs use .toast-region--static so it stays in the page.

Pill toast over media

Over the video picture, a toast is a small scrim pill: no icon, no actions, no dismiss, not focusable, pointer-events: none. It reports a transient status the polite live region also announces ("Back live") and is removed after 1.5 s, which is acceptable only because it is purely decorative duplication of an announcement and carries no action.

Toasts have one size: 24rem wide in the region from 640px, full width below.

Responsive behaviour

  • Below 640px (--layout-breakpoint-sm) the region spans the viewport with 16px side margins and sits above the bottom safe area (env(safe-area-inset-bottom)).
  • From 640px the region is 24rem wide, 24px from the bottom and inline-end edges.
  • The region never covers the focused element (WCAG 2.4.11): pages with a sticky bottom bar raise the region above it, and a toast that would cover the focus target is moved, not shown on top.
  • Text wraps; the action and dismiss buttons stay on the first line's row and wrap below only at 400% zoom.
  • At 400% zoom only the newest toast is shown; the rest queue.

Theming

The toast uses the inverse surface (--color-bg-inverse, --color-fg-inverse) so it contrasts with the page in both themes: dark sage on a light page, near-white on a dark page. Each tone sets --toast-stripe to its status border token; --toast-icon stays the inverse foreground so icons keep contrast on the inverse surface. Buttons inside a toast are re-pointed to inverse colours through the button's component tokens (--btn-fg, --btn-border).

/* A host that wants tone-coloured icons on the toast */
.toast--danger { --toast-icon: var(--color-danger-border); }

The pill toast reads media tokens (--color-media-scrim, --color-media-fg), the same in both page themes because it always sits on video. See theming.

Accessibility

Role and pattern

Toasts are status messages (WCAG 4.1.3). The region contains an empty role="status" container (polite) and an empty role="alert" container (assertive) from page load; toasts are appended into the right one so they are announced without moving focus. Danger toasts go in the alert container; everything else in status. See the APG Alert pattern. The pill toast is aria-hidden because the player's own live region announces the same text.

Keyboard

KeyAction
F6Moves focus to the newest toast's first button (and back to where it was on a second press). Products that cannot use F6 provide another documented shortcut.
Tab / Shift+TabMoves between the action and dismiss buttons inside a toast.
Enter, SpaceActivates Undo, Retry or Dismiss.
EscWhile focus is inside a toast: dismisses it and returns focus to where it was before.

Focus

A toast never takes focus when it appears. Focus inside a toast pauses its timer. When a focused toast is removed (Undo pressed, dismissed), focus returns to the element that had it before entering the region, or to the main heading if that element no longer exists.

Labelling

The region is a <section aria-label="Notifications">. The announcement is the toast's text: title, then body. The dismiss button is named "Dismiss notification"; the action names its effect ("Undo", "Retry"). Anything that offers Undo is also undoable from the page, so a screen reader user who missed the toast is not stuck.

The stripe is a supporting cue only; the icon shape and the words carry the tone. Pairs that fall below 3:1 in one theme (check the live ratios) do not fail 1.4.11 because the stripe is not required to understand the toast.

Motion

Toasts fade out over --duration-base (200 ms) with --ease-exit; they appear without movement. Under prefers-reduced-motion the duration token is zeroed, so they simply disappear.

Touch

Toast buttons are 32px tall (--control-height-sm), above the 24px minimum, with 12px between them. The region itself passes pointer events through (pointer-events: none) so it never blocks the page; only toasts are targets. There are no swipe-to-dismiss gestures without a button alternative.

Content

  • Title: the outcome in past tense, object first: "Assignment saved", "3 learners removed", "Reminder emails not sent". No "Success!".
  • Body (optional): one short sentence of consequence: "4 learners will be notified."
  • Errors say what failed and that the person's work is safe if it is: "Learners could not be loaded. Your selections are safe."
  • Actions: one verb, "Undo", "Retry" or "View". Never "OK" or "Close" as the action; Close is the dismiss button.
  • Maximum about 20 words in total. A longer message is an alert.
