Form layout

Form layout places fields, groups and actions so a form reads top to bottom in one pass: one column by default, paired fields only where they belong together, and one actions bar at the end.

WCAG 2.2 AAStatus: stableNative <form>, <fieldset>

Overview

Use these layout classes for every form: assigning learners, scheduling a session, editing course settings, filtering a table. Each control inside is a form field (label, control, hint, error); this page covers how fields sit together, how groups are named, where actions go, and how a form reports errors and progress.

  • Single column is the default. People scan down one edge and never miss a field.
  • Two column only for short fields that are read as a pair: start and end date, first and last name.
  • Inline for one-line filter or search forms above a table.
  • Settings that apply immediately need no form or actions bar; use switches.
  • For the end-to-end flow (validation timing, saving, success) see the forms pattern.

Anatomy

  1. Form and field stack.form: a column, max 40rem wide, 24px (--space-6) between fields and rows.
  2. Row.form__row, one column; .form__row--2 becomes two equal columns from 48rem, 24px apart.
  3. Fieldset.fieldset with a <legend> names a group (radios, checkboxes, an address). 1px --color-border-default, 16px padding; .fieldset--bare drops the frame.
  4. Actions bar.form__actions: top divider, 16px above, buttons at the end edge with 12px between; primary last. Stacks full width, primary on top, below 48rem.

Sizes

One size. Form spacing is fixed to the 4px scale (24px between fields, 12px between actions); controls inside use their own sizes, which default to 44px.

States

The form's own states live in its actions bar and its error reporting. Pointer and focus states are forced with data-state; products get them from :hover, :focus-visible, :active, disabled and aria-busy.

  • Required fields say "(required)" in the label and set required or aria-required; when most fields are required, mark the optional ones "(optional)" instead.
  • Validation timing: errors appear when a field is left (touched) or on submit, never while typing the first time. The form uses novalidate so the system's messages replace browser bubbles.
  • Disabled form: put disabled on a wrapping <fieldset> and explain why above it; do not disable only the submit button without a reason.

Responsive behaviour

  • .form is fluid up to 40rem, so lines of labels and hints stay readable on wide screens; on phones it takes the full column with --layout-margin on each side.
  • .form__row--2 is one column below --layout-breakpoint-md (48rem / 768px) and two equal columns from there; the DOM order (start, then end) is the reading order at every width.
  • .form__actions below 48rem stacks buttons full width in reverse order, so the primary action is on top and nearest the thumb; from 48rem they sit in a row at the end edge.
  • .form__inline wraps fields and the button onto new rows as space runs out; at 320px each item is full width.
  • At 400% zoom or with 200% text every layout reaches its one-column form; nothing scrolls horizontally.

Theming

Form layout has no component tokens. It reads spacing (--space-3, --space-4, --space-6), --color-border-default for the actions divider and fieldset frame, and the danger tokens for the error summary (--color-danger-bg, --color-danger-border, --color-danger-solid stripe, --color-danger-fg heading and links). The dark theme swaps those semantic values; in forced colours the summary keeps its border and stripe as system colours. Re-skin the fields and buttons through their own component tokens.

Accessibility

Role and pattern

A native <form> with novalidate and the system's own messages, following the W3C WAI forms tutorial and Understanding SC 3.3.1 Error Identification. Groups are <fieldset> with <legend>. A filter form takes role="search". The error summary is role="alert" with tabindex="-1" so it can receive focus.

Keyboard

KeyAction
Tab / Shift+TabMoves through fields in visual order, then the actions bar (Cancel, then the primary action).
Enter in a text fieldSubmits the form (native). In the combobox, Enter submits only when the popup is closed.
Enter on an error summary linkMoves focus to the field and scrolls it into view with its label visible.
EscNo form-level action. Inside a dialog it closes the dialog (confirm first if there are unsaved changes).

Focus

On submit with one error, focus moves to that field; with several, to the error summary. After a successful save, focus stays on the primary button and the result is announced, or moves to the new page's heading. Fields use the shared 3px amber ring. scroll-padding-top keeps focused fields clear of sticky headers.

Labelling

Every control has a visible label; required and optional are in the label text. Hints and errors are linked with aria-describedby, error first. Invalid fields set aria-invalid="true". Each summary link repeats the field's error text so it makes sense alone. Form names: a form that is a landmark (search) has an aria-label; others take their name from the page heading.

The actions divider and fieldset frame use --color-border-default; they are decorative grouping, exempt from 3:1, and the legend carries the group's meaning.

Motion

None in the layout. The submitting spinner keeps turning under reduced motion, slowed to 2 s per revolution, because it reports status.

Touch

Stacked full-width actions below 48rem give 44px-tall, full-width targets with 12px between them. Fields are 44px tall; 24px between fields keeps neighbouring targets apart.

Content

  • The primary action names the outcome: "Save session", "Preview assignment", "Assign 2 learners". Never "Submit" or "OK".
  • The summary heading counts the problems: "There are 2 problems with this session". Each link uses the field's error message: "Enter a session title".
  • Error messages say what to do, in the field's terms: "Select at least one learner.", "Enter an end date after the start date."
  • Legends are short noun phrases or questions: "Session format", "Who should attend?"
  • Live counts beside the primary action use numbers and the item noun: "2 learners selected".
  • Confirmations state the result and the object: "Preview only: 2 learners would be assigned to Workplace safety essentials."

Drift fixed during extraction:

  • Button radius 6px (0.375rem) normalised to --radius-md 8px.
  • Breakpoint 40em written as max-width; actions now stack below --layout-breakpoint-md (48rem), min-width first.
