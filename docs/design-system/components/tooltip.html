Tooltip

A tooltip is a small dark label that appears beside a control on hover and keyboard focus. It names an icon-only button, shows a shortcut, or reveals a learner's full name when a chip has truncated it.

WCAG 2.2 AAStatus: stablerole="tooltip"

Overview

Use a tooltip to repeat or complete text that is already available another way: the name of an icon-only button ("Show outline"), its keyboard shortcut ("Captions C"), or the full text of a truncated label (the combobox chip "Katherine Johnson-Goble…"). Tooltips are supplementary; nothing essential lives only in a tooltip.

  • Text: one short line, up to about 80 characters.
  • With shortcut: the label followed by a .kbd key cap.

Do not use a tooltip for instructions needed to complete a task (use a field hint), for interactive content such as links or buttons (use a dialog or popover), for errors (use an inline message), or on disabled controls that cannot receive focus. Touch users rarely see tooltips, so the information must also be reachable without one.

Anatomy

  1. AnchorThe focusable control the tooltip belongs to. It references the tooltip with aria-labelledby (icon-only) or aria-describedby (extra detail).
  2. Container.tooltip: --color-bg-inverse, --radius-sm, 8 × 12px padding, --shadow-2, max min(24rem, 100vw − 32px).
  3. Text--text-body-sm in --color-fg-inverse; wraps, never truncates.
  4. Shortcut (optional).kbd with a transparent fill and --color-border-inverse edge, 8px after the text.

Variants

Tooltips are drawn in place here with .tooltip--static; in products they float (position: absolute in a .tooltip-anchor, or fixed in the top layer) 4px from the anchor and are hidden until shown.

Choosing the reference

  • Icon-only control: the tooltip text is the name, so the button uses aria-labelledby pointing to the tooltip. Do not also set an aria-label that says something different.
  • Extra detail on a labelled control: aria-describedby.
  • Full value of truncated text: the control's own name already contains the full text ("Remove Katherine Johnson-Goble"), so the tooltip is visual only and is not referenced. It appears only when the label is actually truncated.

Sizes

Tooltips have one size: --text-body-sm on 8 × 12px padding, up to 24rem wide.

States

The tooltip itself has two states, hidden and visible; what changes is what makes it visible. The matrix shows the anchor's state and whether the tooltip is showing.

  • Hover: appears after a 300 ms rest so a passing pointer does not flash it. The combobox full-label tooltip appears at once, because the person is reaching for that chip.
  • Focus: appears immediately on :focus-visible (keyboard), including a chip's remove button.
  • Hovered tooltip: stays visible while the pointer is over the anchor or the tooltip; it hides 250 ms after the pointer leaves both (WCAG 1.4.13 hoverable).
  • Active: stays while the press completes; a toggle's tooltip text updates with its state ("Captions" → "Turn off captions" only if the name changes).
  • Disabled: native disabled controls get no focus and so no tooltip. Use aria-disabled="true" and put the reason in the tooltip and in visible text nearby.
  • Dismissed: Esc hides it without moving focus and without closing anything else; the next Esc goes to the surrounding component (the combobox then closes its popup).

Responsive behaviour

  • Placement: below the anchor, start-aligned, 4px away; it flips above when there is no room and is clamped 8px inside the viewport on both axes, as the combobox mock does. It never covers the anchor or the focused element.
  • Width is capped at min(24rem, 100vw − 32px); long text wraps. At 320px and 400% zoom the tooltip stays within the viewport.
  • On touch screens (hover: none) tooltips appear only on keyboard focus. Icon-only controls that matter on phones need a visible label there, or a name that is obvious from the icon.
  • With WCAG text spacing the tooltip grows; nothing inside it truncates.

Theming

The tooltip is an inverse surface: --color-bg-inverse with --color-fg-inverse text, so it contrasts with the page in both themes. In the light theme it is sage-900 with white text; in the dark theme it flips to sage-25 with sage-900 text. The shortcut key cap inside uses --color-border-inverse. Over media (the video stage), keep the inverse surface; it reads against both the dark scrim and a bright picture.

/* A host with a branded tooltip surface */
.host-shell .tooltip { background: var(--color-accent-active); color: var(--color-fg-on-accent); }

In forced-colours mode the tooltip gains a ButtonText border so it stays distinct from the page. In the shipped packages the combobox tooltip uses its text and surface colours swapped (--t-combobox-text on --t-combobox-surface), the same inverse rule; see theming.

Accessibility

Role and pattern

The WAI-ARIA APG Tooltip pattern: role="tooltip" on the container, referenced from the anchor by aria-labelledby or aria-describedby. It must meet WCAG 1.4.13 Content on Hover or Focus: dismissible, hoverable and persistent.

Keyboard

KeyAction
Tab to the anchorShows the tooltip immediately.
EscHides the tooltip; focus stays on the anchor. The tooltip handles Esc first and stops it, so a containing popup or dialog does not also close.
Tab away / blurHides the tooltip unless the pointer is over it.
Shortcut keyRuns the action shown; the tooltip is a reminder, the shortcut is announced through aria-keyshortcuts.

Focus

The tooltip never receives focus and never contains focusable elements. The anchor shows the normal amber ring. Clicking the tooltip does not move focus (the combobox mock cancels mousedown on it).

Labelling

When the tooltip names an icon-only control, it is the accessible name via aria-labelledby, so the visible and announced names match (2.5.3 Label in Name). The key cap is part of the name only if it reads well ("Captions C" is acceptable; prefer aria-keyshortcuts and hide the cap with aria-hidden when it would be read awkwardly). Tooltips are not announced when they appear; they are read as part of the name or description.

Motion

The tooltip may fade in over --duration-fast; it hides instantly. Reduced motion removes the fade. The show delay is a timing, not an animation, and stays.

Touch

Touch does not show tooltips on press, because the press activates the control. Do not rely on long-press. The anchor itself meets the 44px target; the tooltip is not a target.

Content

  • Name the action, in sentence case, without ending punctuation: "Show outline", "Unmute", "Go to live".
  • Match the control's accessible name exactly when it names an icon button.
  • Shortcuts are single key caps after the text: "Captions C", "Fullscreen F".
  • For truncated values, show the whole value and nothing else: "Katherine Johnson-Goble".
  • One line where possible; never more than two sentences.
