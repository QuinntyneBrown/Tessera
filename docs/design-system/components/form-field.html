Form field

The wrapper every input sits in. It gives a control its visible label, says whether it is required, places the error directly under the control, and keeps the hint, counter and any trailing action on one row below.

Overview

A form field is not a control; it is the column that holds one. Every single-value input uses it: text field, textarea, select, combobox and slider. It fixes three things so no screen has to decide them again:

  • Reading order: label, control, error, then the row below (hint, counter, trailing action). This is the order in the combobox mock after its Fluent 2 review: the error sits directly under the field, before the hint, with an icon.
  • Spacing: 8px (--space-2) between every part, so label, control and messages read as one unit and separate fields (24px apart in a form layout) read as separate units.
  • Wiring: the label is a <label for>; the error, hint and counter are referenced by aria-describedby in that order.

Do not use the wrapper for groups of checkboxes or radio buttons: they share one question, so they use a <fieldset> with a <legend> (.fieldset). A single switch or checkbox carries its own label and does not need it either.

Anatomy

  1. Label.field__label: bold 16px (--text-label at --font-size-md), --color-fg-default. Always visible; never replaced by placeholder text.
  2. Required marker.field__required: the word "(required)" inside the label, regular weight, --color-fg-muted. Part of the accessible name, so it is announced.
  3. ControlAny input: .input, .textarea, .select, .input-group, .combobox. Fills the column width.
  4. Error (conditional).field__error: 16px icon + 14px text in --color-danger-fg, 8px between them. Directly under the control, before the hint.
  5. Hint (optional).field__hint: 14px --color-fg-muted. Stays visible while an error shows.
  6. Counter or trailing action (optional).field__counter (tabular figures) or a .btn--link such as "Clear all selections", pushed to the end of .field__below.

Variants

The wrapper has one look. What varies is which optional parts are present. Add a part only when it carries information the label cannot.

Sizes

The wrapper has one size. The control inside it carries the size (text field and select offer sm, md and lg); label, error and hint stay the same.

States

The wrapper itself does not change on hover or focus; the control does. Invalid adds the error line; disabled and read-only change only the control, while the label stays at full contrast so the field is still readable. Hover, focus and active are forced with data-state for review.

  • Invalid is shown three ways at once: the thicker danger border on the control, the icon, and the text. Never colour alone.
  • When to validate: on submit, then on change for a field that has already shown an error. Not on every keystroke of a first attempt, and not on blur of an empty field the learner simply passed through (the combobox mock validates only after the field was touched).
  • Disabled and read-only keep the label and hint at full contrast. A read-only value is still copyable and still announced; prefer it to disabled for information the person cannot change.

Responsive behaviour

  • The field fills its column (min-width: 0, control at 100%). Column count is the form layout's job: two columns from --layout-breakpoint-md, one below.
  • .field__below wraps: at 320px or 200% text the counter or "Clear all selections" drops under the hint and stays aligned to the end edge, with 4px between the rows.
  • Labels and errors wrap; they never truncate. The error icon stays aligned with the first line of text.
  • With WCAG text-spacing overrides (1.5 line height, 0.12em letter spacing) nothing overlaps, because every part is in normal flow with gaps, not fixed heights.
  • In right-to-left layouts the counter moves to the left edge (margin-inline-start: auto) and the error icon leads on the right.

Theming

The wrapper has no component tokens; it reads three semantic colours (--color-fg-default for the label, --color-fg-muted for marker, hint and counter, --color-danger-fg for the error) and the spacing scale. Re-theme it by scoping those semantic tokens, never by restyling .field__*.

/* A host LMS panel with a tinted surface keeps hint contrast by raising muted text */
.assignment-panel { --color-fg-muted: var(--color-fg-default); }

In the dark theme the error text lightens to --palette-red-200 and the hint to --palette-sage-200, both above 7:1 on the dark surface. In the shipped packages the same decisions are --t-colorNeutralForeground1 (label), --t-colorNeutralForeground2 (hint) and --t-colorPaletteRedForeground1 (error); the combobox exposes them as --t-combobox-text, --t-combobox-placeholder and --t-combobox-error. Accessibility

Role and pattern

No ARIA role: a native <label for> names the control and aria-describedby attaches the error, hint and counter. This follows the WAI-ARIA APG guidance on names and descriptions and the WCAG technique for labels or instructions. The control inside follows its own pattern (for example the APG Combobox).

Keyboard

KeyAction
Tab / Shift+TabMoves to the control, then to any trailing action in the row below ("Clear all selections"). Label, error, hint and counter are not focusable.
Click or tap on the labelFocuses (or toggles) the control, because the label is associated with for; the label is part of the target.
EnterSubmits the form from a single-line input; the wrapper adds nothing.

Focus

The ring is drawn by the control (3px --color-focus-ring, 2px offset); the wrapper never draws one. On a failed submit, focus moves to the error summary at the top of the form, whose links move focus to each invalid control (see forms). Errors never steal focus while the person is typing.

Labelling

  • The visible label text is the accessible name; "(required)" is inside the label, so it is announced with the name, and the control also carries required (or aria-required="true" on a combobox).
  • aria-describedby lists the error first, then the hint, then the counter: "Select at least one learner. Select one or more learners…" The error id is added only while the error is visible.
  • aria-invalid="true" is set with the error and removed with it.
  • The error icon is aria-hidden="true"; the text says what is wrong.

Motion

The error appears and disappears without animation, so nothing moves under the pointer and the layout shift is immediate. Only the control's border colour transitions (--duration-fast, zeroed under reduced motion).

Touch

The label enlarges the control's target: tapping it focuses the input. Trailing actions in the row below are at least 24px tall (.btn--link uses --target-min) and sit 16px from the hint.

Content

  • Label: a noun phrase in sentence case, no colon: "Learners", "Course title", "Passing score". Never a question unless the whole form is a questionnaire.
  • Required: mark required fields with "(required)". If almost every field is required, say so once at the top and mark the few optional ones "(optional)" instead.
  • Hint: one sentence that helps the person succeed: format, where the value appears, limits. "Select one or more learners. Search to narrow the results." Not a repeat of the label.
  • Error: what to do, not what went wrong: "Select at least one learner.", "Enter a course title.", "Enter a score from 0 to 100." No "Invalid input", no "Error:", no blame.
  • Counter: "63 of 200 characters"; over the limit, "12 characters too many". The counter states the limit before it is reached.
  • Placeholder: an example value at most ("Name or email"), never the label or the hint, because it disappears on input.
