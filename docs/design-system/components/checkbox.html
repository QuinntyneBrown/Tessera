Checkbox

A checkbox turns one independent option on or off as part of a form: agree to the course terms, choose which reminders to send, pick the sessions a learner attends. Several checkboxes answering one question sit in a fieldset with a legend.

WCAG 2.2 AAStatus: stableNative <input type="checkbox">

Overview

Use a checkbox when each option can be on or off independently of the others, and the choice takes effect when the form is submitted. Tessera uses the native input, sized to 20px and tinted with accent-color, exactly as the combobox mock's "Right-to-left" control does.

  • Exactly one option from a set: use a radio group.
  • A setting that applies immediately, with no submit (captions on, right-to-left preview): use a switch.
  • Choosing many items from a long or searchable list (assigning learners): use the combobox, whose options show a check mark (.combobox__check) but are listbox options, not checkboxes.

Anatomy

  1. BoxNative checkbox, 1.25rem (20px) square, accent-color: --color-accent. Aligned to the first line of the label (2px top margin).
  2. Label16px --text-body, --color-fg-default; 8px (--space-2) from the box. Clicking it toggles the box.
  3. Description (optional).check__description: 14px --color-fg-muted, linked with aria-describedby.
  4. Row.check: at least 44px tall (--control-height-md) with 8px block padding, so stacked rows are 44px targets with no gap.

Not a checkbox: .combobox__check draws the same 20px box for aria-selected options, dashed when the option is disabled. See combobox.

Sizes

One size: a 20px box in a 44px row. Scaling the box separately from the text breaks alignment; it grows with browser zoom instead.

States

The box is drawn by the browser, tinted with accent-color, so its hover and pressed shading come from the browser and cannot be forced in a static page; those cells use data-state for reference and show the browser default. Focus is forced with data-state="focus". Indeterminate boxes are set by the short script at the end of this page.

Same order as a form field: options, then the error with its icon, then the hint. The fieldset is described by both.

Both themes

  • Checked fills the box with --color-accent and draws a tick in a contrasting colour chosen by the browser; the tick shape, not the colour, is the cue.
  • Indeterminate (a dash) only exists on a parent that summarises children. It is a script property, never set by markup; activating it checks every child.
  • Invalid draws a 2px --color-danger-solid outline 1px outside the box, plus the error message below the group.
  • Disabled keeps the label readable in --color-fg-disabled; the browser greys the box. Explain why nearby if the option could become available.

Responsive behaviour

  • Long labels wrap beside the box; the box stays aligned to the first line. Labels never truncate.
  • Horizontal groups (.check-group--horizontal) wrap onto new lines with a 24px column gap; at 320px they become a column naturally. Use them only for two to four short options.
  • Cards are full width. In a wide form, place them in a form layout row to get two columns from --layout-breakpoint-md.
  • At 200% text and with WCAG text spacing, rows grow taller; the 44px minimum height is a floor, not a fixed height.

Theming

The checkbox reads --color-accent through accent-color; the browser picks the tick colour for contrast. Text uses --color-fg-default, --color-fg-muted and --color-fg-disabled; cards use --color-border-strong, and when checked --color-accent and --color-accent-subtle. There are no checkbox component tokens: theme it by scoping the semantic tokens.

/* A host LMS whose brand is a different hue */
.host-brand { --color-accent: var(--palette-teal-700); }

In dark the accent lightens to --palette-teal-300 and the browser draws a dark tick on it; the checked card tint becomes --palette-sage-800. The shipped combobox exposes the selection mark as --t-combobox-selected-mark (aliases --t-colorBrandBackground). See theming.

Accessibility

Role and pattern

Native <input type="checkbox">, following the WAI-ARIA APG Checkbox pattern (dual-state, and mixed-state for "select all"). Groups use <fieldset> and <legend>, not role="group". No ARIA role is added; the indeterminate property is exposed as mixed automatically.

Keyboard

KeyAction
Tab / Shift+TabMoves to the next or previous checkbox. Every checkbox is its own tab stop (unlike radios). Disabled ones are skipped.
SpaceToggles the focused checkbox. On an indeterminate parent, checks all children.
EnterNo effect on the checkbox; it does not toggle.

Focus

The shared ring (3px --color-focus-ring, 2px offset) on the box itself, on :focus-visible. On a card the ring is still on the box; the card edge does not change with focus. On a failed submit, the error summary links to the first checkbox in the group.

Labelling

  • Every checkbox has a label: a wrapping <label>, or <label for> when a description sits beside it. Cards use aria-labelledby on the title so the description is not part of the name.
  • Descriptions use aria-describedby.
  • A group's question is its <legend>; "(required)" goes in the legend; the fieldset is described by the error and hint.
  • A "select all" parent names its children with aria-controls.
  • The combobox check mark is aria-hidden; the option's aria-selected carries the state.

The unchecked box border is drawn by the browser (Chromium and Firefox use a mid-grey above 3:1 on light and dark surfaces); forced-colours mode hands the box to system colours.

Motion

No animation: the tick appears instantly. Nothing to reduce.

Touch

The box is 20px, but the target is the whole row: the label is part of it, and each row is at least 44px tall with no dead gap between rows (the 44px row comes from the combobox mock's control row). Cards are the target in full. Hover changes are not relied on.

Content

  • Write the label as the thing that becomes true when checked: "Issue a certificate", "Allow retakes". Avoid negatives ("Don't send reminders").
  • Sentence case, no trailing full stop, no "Click to…".
  • The legend asks the question or names the set: "Send reminders", "Course formats", "Sessions Alan Turing attends".
  • Descriptions explain consequences in one sentence: "The highest score is kept."
  • Errors say what to do: "Choose at least one reminder." For a required single checkbox: "Confirm you have read the code of conduct."

Sources

Extracted from these mocks:

  • combobox: the "Right-to-left" checkbox in the "Mock states" control row (1.25rem box, accent-color, 44px label rows, 0.5rem gap); the option check mark .combobox__check (1.25rem, 4px radius, accent fill when selected, dashed when disabled); the Fluent 2 comparison's decision to show selection by the check mark, not a row tint.

Derived: groups, descriptions, cards, indeterminate and invalid states are not in the mocks; they follow the system rules.

Drift fixed during extraction:

  • The mock's checkbox changed the page direction immediately; documented as a switch case, with checkboxes reserved for values submitted with a form.
  • Combobox selected options had both a check mark and a green row tint; the tint is dropped, the mark is the cue.
  • Disabled options were meant to be italic with a dashed mark but rendered upright; .combobox__option[aria-disabled] now sets italic and the dashed mark.
  • Mock state panel text at 0.85rem snapped to --font-size-sm; checkbox labels in forms use 16px.
