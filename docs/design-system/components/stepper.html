Stepper

The stepper is the SCORM player's course outline: an ordered list of lessons, each with a number marker, a title and a one-line detail, that shows where the learner is, what is complete and what is locked, and lets them jump to any lesson they are allowed to open.

Overview

Use a stepper when content has a fixed order and each step has a status: the activities (SCOs) of a SCORM course, or the steps of a short wizard such as assigning a course. The order matters, progress is reported per step, and some steps can be locked by sequencing rules until earlier ones are complete.

  • Vertical (default): the SCORM outline. Each item is a <button> that loads that lesson into the player; title and detail stack beside the marker.
  • Horizontal (.stepper--horizontal): a compact progress indicator above a multi-step form ("Choose course · Choose learners · Schedule · Review"). Items are usually status only, not buttons.

Use tabs for parallel views with no order, sidebar navigation for pages, and a progress bar when only the overall percentage matters. Completion comes from the course content, never from the outline: selecting a lesson only opens it.

Anatomy

  1. Current stripeInset 4px --color-accent (--border-width-stripe) on the start edge plus --color-accent-subtle fill; only on aria-current="step".
  2. Marker.stepper__marker: a 1.75em circle with the lesson number, or "✓" when complete, "!" on error; aria-hidden="true". 1px --color-border-strong edge; dashed when locked.
  3. Title.stepper__title: bold 14px (--text-label), snug line height; the button's name via aria-labelledby.
  4. Detail.stepper__detail: 12px muted (--text-caption): status, or the reason a lesson is locked; the button's description via aria-describedby.
  5. Item.stepper__item: a full-width <button>, 12px padding, --radius-md, start-aligned text, at least 44px tall.

Sizes

The stepper has one size: 12px item padding, a 1.75em marker and 14px titles. It scales with the root font size.

Both themes

  • Current (aria-current="step"): accent-subtle fill, accent title, inset 4px accent stripe; the detail starts with "Current activity". In forced-colours mode a 2px Highlight outline replaces the fill.
  • Complete (data-complete="true"): accent-filled marker with "✓" and the detail "Complete". Set only when the content reports completion.
  • Locked (aria-disabled="true"): readable --color-fg-disabled text, dashed marker edge, the reason as the detail. It stays focusable (not disabled) so the reason can be reached; activation is ignored.
  • Error (data-error="true"): danger-tinted marker with "!", and the detail says what failed and what to do. Colour is never the only cue.
  • Active has no separate look; activation opens the lesson immediately.

Responsive behaviour

  • Layout: the outline and the player share a wrapping .sidebar-layout. The outline column has a 15.5rem basis; the player keeps at least 30rem, so whenever the player cannot keep 30rem (narrow screens, 200% text, 400% zoom) the outline stacks above it instead of squeezing it.
  • Below 48rem (the mock's 47.5em): the outline list is hidden behind a "Show outline" button (.outline-panel__toggle, aria-controls="outline", aria-expanded). Opening it changes the label to "Hide outline".
  • Choosing a lesson from the open compact outline closes the outline and moves focus to the activity heading, so the learner lands on the content.
  • If the outline closes while focus is inside it, focus moves to the toggle. If the window widens past 48rem while the toggle has focus, the toggle disappears and focus moves to the current lesson, never to <body>.
  • Horizontal steppers wrap onto more rows; below 48rem use the vertical layout (drop .stepper--horizontal) so titles are not crushed.
  • Titles and details wrap; they are never truncated.

Theming

The stepper reads semantic tokens directly: --color-accent-subtle, --color-accent and --color-fg-accent (current), --color-accent + --color-fg-on-accent (complete marker), --color-danger-bg, --color-danger-solid and --color-danger-fg (error marker), --color-border-strong (marker edge), --color-fg-muted (detail) and --color-fg-disabled (locked). There are no component tokens.

/* An LMS that shows completion in its success colour */
.lms-outline .stepper__item[data-complete="true"] .stepper__marker {
  border-color: var(--color-success-solid); background: var(--color-success-solid);
}

In the dark theme the fill becomes a deep teal and the stripe and complete marker lighten with the accent. In the shipped SCORM player these map to --t-colorBrandBackground and --t-colorBrandForeground1; see theming.

Accessibility

Role and pattern

An ordered list (<ol role="list">; the explicit role keeps list semantics in Safari once list-style is removed) inside a <nav> labelled by the "Course outline" heading. Each lesson is a native <button>; the current one has aria-current="step". The compact toggle follows the WAI-ARIA APG Disclosure pattern. Locked lessons use aria-disabled as in the APG Button pattern. This is not a tablist or a listbox: there is no arrow-key navigation.

Keyboard

KeyAction
Tab / Shift+TabMoves through the outline toggle (below 48rem) and every lesson button, including locked ones.
Enter, SpaceOn a lesson: opens it, then moves focus to the activity heading. On a locked lesson: nothing happens; the reason was already announced as its description. On the toggle: shows or hides the outline.

Focus

The shared 3px amber ring with a 2px offset. After a lesson opens, focus moves to the activity heading (tabindex="-1"), which announces the new lesson. Focus is never stranded on <body>: a closing outline returns focus to the toggle, and widening past 48rem moves focus from the vanished toggle to the current lesson.

Labelling

Each button is named by its title (aria-labelledby) and described by its detail (aria-describedby), so a screen reader says "Put it into practice, button, current step / dimmed, Locked until Give useful feedback is complete." The marker is aria-hidden; the number is conveyed by the list position, and "Complete" by the detail. Status changes ("Ask better questions complete.") are announced through the player's polite live region, not by re-rendering the outline into a live region.

Motion

The item background transitions over --duration-fast only under prefers-reduced-motion: no-preference (as in the mock); otherwise state changes are instant. The outline opens and closes without animation.

Touch

Each lesson button is the full width of the panel and at least 44px tall (12px padding around a two-line title and detail). The compact toggle is a 44px button. Nothing depends on hover.

Content

  • Titles are the lesson's own title from the manifest, in sentence case: "Ask better questions".
  • Details are short status phrases joined with " · ": "Current activity · Not reported", "Complete".
  • Locked details say what unlocks the lesson, naming it: "Locked until “Give useful feedback” is complete." Never just "Locked".
  • Error details say what failed and the next step: "Could not load. Select to try again."
  • Use "Not reported" rather than "Incomplete" when the content has not sent a status; the player does not guess.
  • The toggle says "Show outline" / "Hide outline"; the position text above the player says "Activity 2 of 4".

<script>
  // From the SCORM mock: below 47.5em (48rem here) the outline hides behind its toggle.
  const compact = () => matchMedia('(max-width: 47.99rem)').matches;
  function setOutline(open) {
    toggle.setAttribute('aria-expanded', String(open));
    toggle.textContent = open ? 'Hide outline' : 'Show outline';
    outline.hidden = compact() && !open;
    if (outline.hidden && outline.contains(document.activeElement)) toggle.focus();
  }
  function goTo(i, fromOutline) {
    if (blockedReason(i)) return;              // aria-disabled lessons ignore activation
    if (fromOutline && compact()) setOutline(false);
    render();
    activityHeading.focus();
  }
</script>
