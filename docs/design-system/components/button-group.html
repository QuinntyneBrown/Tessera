Button group

A button group keeps related buttons together and names them as a set. The segmented form picks one view or option among two to five ("List" or "Grid"); the toolbar form holds the actions an administrator takes on one thing, such as the learners selected in a course.

WCAG 2.2 AAStatus: stablerole="group" / role="toolbar"

Overview

Use a button group when several buttons act on the same thing and read better as one unit than as loose buttons. The group gets one accessible name ("Outline filter", "Learner actions"), so a screen reader user hears what the set is for before they hear each button.

  • Segmented (.btn-group--segmented): two to five mutually exclusive options that apply immediately, such as the outline filter "All lessons / Incomplete" or the results view "List / Grid". Exactly one segment is pressed at all times (aria-pressed="true").
  • Toolbar (.btn-group with role="toolbar"): a row of actions on one object, such as "Assign", "Message" and "Export" above a learner table. Arrow keys move between the buttons and the whole toolbar is one Tab stop.
  • Action group (.btn-group with role="group"): loose related buttons that keep their own Tab stops, such as the media controls. Use this, not a toolbar, when arrow keys already mean something else, as in the video player, where arrows change the volume.

Do not use a segmented group to switch between panels of content; that is tabs. Do not use it for a value submitted with a form; that is a radio group. More than five options, or options with long labels, belong in a select. A single on/off setting is one toggle button or a switch.

Anatomy

  1. Group.btn-group with role="group" (or toolbar) and an aria-label that names the set. No visual frame of its own.
  2. Pressed segmentaria-pressed="true": --color-accent-subtle fill, --color-accent edge, --color-fg-accent label. Raised above its neighbours so its whole edge shows.
  3. Shared edgeNeighbouring segments overlap by one hairline (-1px margin) so the group reads as one control with a single 1px divider.
  4. SegmentA normal .btn: 44px tall, --text-label, square inner corners; only the outer corners take --radius-md.

Variants

Segmented (single select)

The pressed segment is the current choice. Choosing another segment presses it and releases the previous one; pressing the current segment again does nothing, so there is never zero or two choices.

Text segments, and icon-only segments that carry aria-label and a tooltip.
HTML
<div class="btn-group btn-group--segmented" role="group" aria-label="Outline filter">
  <button class="btn" type="button" aria-pressed="true">All lessons</button>
  <button class="btn" type="button" aria-pressed="false">Incomplete</button>
  <button class="btn" type="button" aria-pressed="false">Complete</button>
</div>

Toolbar

Actions on one object, spaced 8px apart. The toolbar is a single Tab stop; Left and Right arrows move between its buttons (roving tabindex). A vertical divider may separate clusters; the last item can be a "More actions" menu button.

One Tab stop; only the current button has tabindex="0".
HTML
<div class="btn-group" role="toolbar" aria-label="Actions for 3 selected learners">
  <button class="btn" type="button" tabindex="0">…Assign</button>
  <button class="btn" type="button" tabindex="-1">…Message</button>
  <button class="btn" type="button" tabindex="-1">…Export</button>
  <hr class="divider divider--vertical" aria-orientation="vertical">
  <button class="btn btn--icon" type="button" tabindex="-1" aria-label="More actions"
          aria-haspopup="menu" aria-expanded="false">…</button>
</div>

Action group

Related buttons that each keep their own Tab stop. Toggle buttons inside it use aria-pressed independently (any number can be on), as the video player's Mute, Captions and Fullscreen do.

Independent toggles: each button's pressed state is its own.

Sizes

The group has no size of its own; it takes the size of its buttons. Use medium (44px) by default. Small (32px) is for dense surfaces where the row around it is also a target, such as a card header or a table toolbar on a wide screen. Never mix sizes in one group.

sm: .btn--sm on every segment (32px, --space-3 padding). md: default (44px, --space-4).

States

Each button in a group has the button states. Pointer and focus states are forced here with data-state; products get them from :hover, :focus-visible, :active and disabled.

Focus ring sits above the neighbours; an unavailable segment stays focusable with a reason; a disabled group keeps the pressed segment visible.
  • Pressed: fill, edge and label colour all change, and aria-pressed is announced ("List view, toggle button, pressed"). Pressed is never shown by colour alone: the fill change is backed by the accent edge.
  • Loading: when choosing a segment fetches data (switching to "Incomplete" reloads the outline), the chosen segment is pressed at once and shows aria-busy="true" until the content arrives; the result is announced by the content's live region.
  • Disabled: dashed edge, readable label. Prefer aria-disabled="true" with a reason for a single unavailable option so it can still be found.

Both themes

Responsive behaviour

  • Toolbar and action groups wrap (flex-wrap: wrap, 8px row and column gap). Below --layout-breakpoint-md (768px), move everything after the first two actions into the "More actions" menu so the row stays one line.
  • Segmented groups do not wrap gracefully: a wrapped segment loses its joined edge. Keep labels to one or two words so the group fits at 320px with 200% text. On phones the group may span the full width with equal segments; if it still does not fit, use a select.
  • Labels never truncate. With WCAG text spacing applied the segments grow taller; they never clip.
  • Medium segments meet the 44px touch target; small segments (32px) exceed the 24px minimum and sit only in rows that are also targets.
Full-width segmented group at 320px: equal segments, shortened labels.

Theming

The group adds no colour of its own. Its buttons read the --btn-* component tokens, and the pressed state overrides them with --color-accent-subtle (fill), --color-accent-subtle-hover (hover fill), --color-accent (edge) and --color-fg-accent (label). The joined corners use --radius-md; the overlap uses --border-width-hairline.

/* A host re-skins pressed segments without touching .btn-group */
.course-tools .btn-group--segmented .btn[aria-pressed="true"] {
  --btn-bg: var(--color-accent);
  --btn-fg: var(--color-fg-on-accent);
}

In the dark theme the pressed fill becomes --palette-sage-800 and the edge and label lighten to --palette-teal-300, keeping the label above 4.5:1. In the shipped packages these map to --t-colorBrandStroke1 (edge) and --t-colorBrandForeground1 (label); see theming.

Accessibility

Role and pattern

Segmented and action groups are role="group" with aria-label, containing native buttons that follow the WAI-ARIA APG Button pattern (toggle buttons via aria-pressed). The toolbar follows the APG Toolbar pattern. The video player's control bar is deliberately a group, not a toolbar, because its arrow keys change the volume.

Keyboard

KeyAction
Tab / Shift+TabSegmented and action groups: moves through each button in order. Toolbar: enters at the last-focused button and leaves the toolbar in one step.
Enter, SpaceActivates the focused button. In a segmented group it presses that segment and releases the previous one.
← / →Toolbar only: moves focus to the previous or next button, wrapping at the ends. Mirrored in right-to-left layouts.
Home / EndToolbar only: moves focus to the first or last button.
↓ on a menu buttonOpens the "More actions" menu and focuses its first item.

Focus

The shared amber ring (3px, 2px offset) appears on :focus-visible. The focused segment is lifted to --z-raised so its ring is not hidden under a neighbour. Choosing a segment keeps focus on it; content that changes elsewhere is announced, focus is not moved.

Labelling

Every group has an aria-label naming the set ("Outline filter", "Actions for 3 selected learners"); a visible heading can be referenced with aria-labelledby instead. Icon-only segments need aria-label ("List view"). Do not repeat the group name in each button. A segmented button's label stays the same whether it is pressed or not; the state comes from aria-pressed.

Motion

Background, border and colour transition over --duration-fast; the active segment shifts 1px. Reduced motion zeroes the duration and removes the shift. The loading spinner keeps turning, slowed to 2 s per revolution.

Touch

Medium segments are 44px tall and at least 44px wide (icon segments are square). Neighbouring segments share an edge, so there is no dead gap between them; each still meets the 24px minimum on its own. Hover styles apply only under (hover: hover).

Content

  • Segment labels are short nouns or adjectives in sentence case: "List", "Grid", "All lessons", "Incomplete". One or two words.
  • Keep segment labels parallel: all nouns or all states, never "List" next to "Show as grid".
  • Toolbar labels are verbs: "Assign", "Message", "Export". Name the object in the group label, not in every button.
  • The group label says what is controlled: "Outline filter", "Results view", "Actions for Grace Hopper".
  • Order segments by logic (All, Incomplete, Complete) or frequency, and keep that order on every page.

Code

<!-- Segmented: one choice, applies at once -->
<div class="btn-group btn-group--segmented" role="group" aria-label="Results view">
  <button class="btn" type="button" aria-pressed="true">List</button>
  <button class="btn" type="button" aria-pressed="false">Grid</button>
</div>

<script>
  group.addEventListener('click', (event) => {
    const choice = event.target.closest('button[aria-pressed]');
    if (!choice || choice.getAttribute('aria-pressed') === 'true') return;
    group.querySelectorAll('[aria-pressed]').forEach((b) => b.setAttribute('aria-pressed', String(b === choice)));
  });
</script>

Sources

No mock has a segmented control or toolbar; this component is derived from the nearest evidence and follows the system rules.

  • video-player: the control bar is role="group" named "Player controls" with Mute, Captions and Fullscreen as aria-pressed toggles; it is not a toolbar because arrow keys change the volume. That decision is the rule for choosing group versus toolbar.
  • combobox: the "Mock states" Preview chrome groups Preview and Theme selects, a Right-to-left checkbox and Reset in one labelled row; its Light / Dark / System choice is the model segmented use, and its twelve-option Preview list is the model for "too many, use a select".
  • scorm-player: Previous / Next action row and the button visuals segments inherit.

Drift fixed during extraction:

  • Mock chrome buttons used radius 7px (video) and 6px (combobox); segments use --radius-md (8px) on outer corners.
  • Button weight 750; normalised to 700 (--font-weight-bold).
  • Video mock-state controls used padding 0.45rem 0.7rem and gap 0.6rem; snapped to --space-2 / --space-4 and an 8px group gap.
  • Pressed states in the video mock were shown only by icon swap; the group adds a visible pressed fill and edge so state does not rely on the icon alone.
