Menu

A menu puts several actions on one thing behind a single button: "Actions for Ada Lovelace", "More actions", "Columns". It opens on demand, is operated with arrow keys, and closes as soon as an action is chosen.

Overview

Use a menu when one trigger offers three or more actions and showing them all would crowd the view: row actions in a learner table, "More actions" at the end of a toolbar, a column picker. Menus hold actions and settings toggles only.

  • Choosing a value for a form field is a select or combobox, not a menu.
  • Moving between pages is links or navigation; a site navigation is never role="menu".
  • Two actions fit as buttons; do not hide them in a menu.
  • Content with headings, forms or explanations is a dialog.

Anatomy

  1. TriggerA .btn with aria-haspopup="menu", aria-expanded and aria-controls; a chevron (or kebab for icon-only) shows it opens something.
  2. Section label (optional).menu__section: overline text naming a role="group" of items.
  3. Item.menu__item with role="menuitem": 44px tall, 12px padding, --text-body-sm, optional leading icon.
  4. Shortcut (optional).menu__shortcut at the end, --color-fg-muted; mirrored in aria-keyshortcuts.
  5. Active itemThe focused item shows a 2px --color-accent outline inset by 2px, the same treatment as the combobox popup's active option.
  6. Separator and danger item.menu__separator (hairline, --color-border-default) sets destructive items apart; .menu__item--danger uses --color-danger-fg.

Sizes

Menus have one size: 44px items with 12px inline padding, 12rem to 20rem wide. Density comes from fewer items, not smaller ones.

States

Hover and focus are forced with data-state. Focus in a menu is the active item: a 2px accent outline inset inside the item, reused from the combobox popup's active option so the active row in any popup looks the same.

Trigger

Open (aria-expanded="true") keeps the trigger in its pressed fill while the menu is showing.
  • Active (pressed): no separate pressed look; activation happens on release and the menu closes at once (checkable items show the new check).
  • Disabled item: aria-disabled="true", readable italic label, still reachable with arrows so its name is heard. Activating it does nothing. If a reason helps, say it in the item ("Download certificates (none yet)").
  • Loading: when items depend on a request, open the menu at once with a single role="menuitem" aria-disabled row reading "Loading actions…"; never leave the trigger dead.

Both themes

Responsive behaviour

  • Width is 12rem minimum and min(20rem, 100vw − 32px) maximum, so the menu never overflows a 320px viewport. Labels wrap inside the item rather than truncate.
  • The menu opens below and aligned to the trigger's start edge; it flips above or to the end edge when there is no room, and its height is capped to the visual viewport with internal scrolling, as the combobox popup is. At 400% zoom it scrolls; it never covers its own trigger.
  • On phones it stays a popup (not a sheet); keep menus to about seven items so they fit without scrolling.
  • Items are 44px tall at every width; shortcuts are hidden below --layout-breakpoint-sm when the label would wrap, since touch users cannot use them.

Theming

The menu reads two component tokens, --menu-bg (--color-bg-surface-raised) and --menu-border (--color-border-strong), plus --shadow-3 and --radius-md, the same values as the combobox popup. The checked box uses --color-accent with an inset ring in --menu-bg, so it follows any re-skin.

/* A host draws menus on its own raised colour */
.host-shell .menu { --menu-bg: var(--color-bg-surface); --menu-border: var(--color-border-strong); }

In the dark theme the menu sits on --palette-sage-850 with a darker --shadow-3; the active outline lightens to --palette-teal-300 and danger text to --palette-red-200. In the shipped packages the surface, border and shadow are --t-colorNeutralBackground1, --t-colorNeutralStrokeAccessible and --t-shadow4; see theming.

Accessibility

Role and pattern

The WAI-ARIA APG Menu Button pattern with the Menu roles: the trigger is a native button with aria-haspopup="menu", aria-expanded and aria-controls; the popup is role="menu" labelled by the trigger; items are menuitem, menuitemcheckbox or menuitemradio; sections are role="group" with aria-labelledby; separators are <hr> (role="separator").

Focus

DOM focus moves into the menu (items have tabindex="-1"), so the focused item is the active one. Its indicator is a 2px --color-accent outline inset by 2px, the combobox popup's active-option treatment; it stays inside the item so neighbouring items never cover it. Closing by Esc, Tab-out or activation returns focus to the trigger, except when the action removes the trigger's row: then focus moves to the next row's trigger, or to the table heading if none is left, never to <body>.

Labelling

The menu is labelled by its trigger (aria-labelledby). Icon-only triggers name the object: "Actions for Ada Lovelace", not "More". Item labels are the accessible names; icons are aria-hidden. The visible shortcut is aria-hidden and repeated as aria-keyshortcuts so it is announced once, correctly. Section labels are read when focus enters the group.

Motion

The menu appears without animation. A product may fade it in over --duration-fast with --ease-enter; reduced motion zeroes the duration. Never animate height, which delays the first item being reachable.

Touch

Items are 44px tall and full width. Tapping outside closes the menu without activating anything underneath. Hover fills apply only under (hover: hover).

Content

  • Items are verb phrases in sentence case: "View progress", "Send reminder", "Export as CSV".
  • End with an ellipsis (…) only when the item opens a dialog that asks for more ("Remove 3 learners…", "Change due date…").
  • Danger items name the loss and the count: "Remove from course…", not "Delete".
  • Put the most frequent item first and destructive items last, after a separator.
  • Section labels are one or two words: "Assignment", "Export", "Sort by".
  • Checkable labels name the thing that is on, not the action: "Score" (checked), not "Show score".

Sources

Derived: not present in the mocks; follows the system rules. Visual and interaction details are borrowed from the nearest evidence:

  • combobox: the popup surface (4px padding, 1px strong edge, 8px radius, 0 0.5rem 1rem shadow) and the active option's 2px accent outline at −2px offset, reused for the active menu item; Escape closing the popup before anything else; the popup bounded by the visual viewport.
  • scorm-player: the "focus never strands on <body>" rule when a region closes, applied to items that remove their own row.
  • video-player: single-letter shortcuts (C, M, F) shown in the notes, the model for .menu__shortcut.

Drift fixed during extraction:

  • The combobox popup shadow was written as a raw rgb(0 0 0 / 0.14); it is --shadow-3 here and darkens in the dark theme.
  • The active outline used a component-only token (--t-combobox-active-outline, the accent in both themes); menus read --color-accent directly.
