Combobox

The combobox finds people or things in a large, server-searched set and keeps every choice visible as a removable chip. In an LMS it is how an administrator assigns learners to a course.

Overview

Use the combobox when the set is too large to show at once, lives on a server, and a person may pick several items: learners for an assignment, instructors for a session, courses for a learning path. Typing searches; arrows browse; every selection becomes a chip in the field, and the popup stays open so several people can be added in a row.

  • Use a select for a short, fixed list of fewer than about ten options (lesson status, time zone).
  • Use a radio group or checkboxes when every option should be visible at once (two to seven choices).
  • Use a text field for free text. Tessera's combobox accepts only listed items; there is no free-form entry in v1.
  • Do not put a combobox in a toolbar or table cell; it needs its label, hint row and popup space.

@tessera/combobox is multi-select. The single-select layout below is documented so products stay consistent, but it is not part of the v1 package; build it from a select until it ships.

Anatomy

  1. Label.field__label, bold 16px, 8px above the field. Required fields add "(required)" in text, not only an asterisk.
  2. Chips.combobox__chips list (aria-label="Selected values") of .chip.chip--removable: 32px tall, --radius-sm, teal-subtle fill, 28px remove button named "Remove {name}". Scrolls vertically after 8rem.
  3. Input.combobox__input, the role="combobox" element. Shares the field's wrapping rows with the chips and drops to its own row when they fill one. Placeholder is a hint ("Name or email").
  4. Spinner and toggle.spinner--sm while a request is in flight; .combobox__icon-btn chevron, 32px, tabindex="-1", named "Show options" / "Hide options".
  5. Popup with listbox.combobox__popup: raised surface, --shadow-3, --radius-md; the .combobox__listbox scrolls. Each option has a filled checkbox, a name and an optional detail line.
  6. Status row.combobox__status: one line under the list with the count or message and a small Retry / Load more button. Outside the list and the Tab sequence.
  7. Error.field__error with an icon, directly below the field and before the hint. First in aria-describedby.
  8. Hint row with Clear all.field__below: hint text, then a link-style "Clear all selections" button (.combobox__clear) at the row's end, so it is never mistaken for "clear the search text".

DOM and reading order is label, field (chips, input, spinner, toggle), popup, error, hint row. The popup follows the field in the DOM so VoiceOver on iOS can swipe from the input into the options; in the product it renders inline in the browser top layer.

              Responsive behaviour

              • Width. The combobox fills its form column (.form caps it at 40rem). At 320px the input keeps at least 8rem beside the toggle; the short placeholder "Name or email" fits without clipping.
              • Chips. Chips and the input share the field's wrapping rows. When the chips fill a row the input drops to its own row; after 8rem of chips the list scrolls vertically, never horizontally. Long chip labels ellipsize inside the field width and keep their full text in the tooltip and the remove button's name.
              • Popup height. The preferred height is 24rem, so it scales with root text size, and it is bounded by the visual viewport (max-height: min(24rem, 60dvh) here; --t-combobox-panel-max-height in the package). At 24rem at least five two-line options and the status row are visible.
              • Short viewports. When the status row and a usable part of the list do not fit around the whole field (a phone in landscape, an on-screen keyboard, 400% zoom), the popup anchors vertically to the input row instead, keeping the field's full width. It may cover chips, but never the input; opening and reflow keep the focused input in view.
              • Status row. The count and the Retry / Load more button sit on one line and wrap at narrow widths.
              • Coarse pointers. Under (pointer: coarse) the input row, toggle, chip remove buttons, status-row buttons and Clear all grow to 44px (2.75rem). With a fine pointer they are 32px (28px for chip remove), above the 24px minimum.
              • Zoom, text size and spacing. Every length is in rem, so 200% text and WCAG text-spacing overrides grow rows rather than clip them. Option text wraps; nothing in the popup truncates.

              Accessibility

              Role and pattern

              The input is an editable combobox with list autocomplete (role="combobox", aria-autocomplete="list", aria-expanded, aria-controls while open, aria-activedescendant), following the WAI-ARIA APG Combobox pattern. The popup holds a role="listbox" with aria-multiselectable="true" and role="option" children with aria-selected; there is no role="region" wrapper. Chips are a plain list of native buttons. The multi-select extension of the pattern needs manual screen reader verification with JAWS, NVDA, VoiceOver (macOS and iOS), TalkBack and Narrator before release.

              Keyboard

              KeyAction
              ↓Closed: opens at the first enabled result. Open: moves to the next option without wrapping; at the last option it requests the next page.
              ↑Closed: opens at the last loaded result. Open: moves to the previous option without wrapping.
              Alt+↓ / Alt+↑Opens with no active option / closes.
              Page Down / Page UpMoves by the number of fully visible options; Page Down on the last option requests another page.
              EnterOpen: toggles the active enabled option, retries after an error, or loads more when no option is active. Closed: submits the form natively.
              SpaceAfter arrow or Page navigation, toggles the active option. After typing or moving the text cursor, types a space.
              Home / EndMove the text cursor (native), not the active option.
              EscDismisses a full-label tooltip first, then closes the popup, then clears a non-empty query. Propagates only when closed and empty, so a surrounding dialog can close.
              Tab / Shift+TabCloses the popup and follows the form's focus order. The toggle and status-row buttons are not Tab stops.
              Backspace (empty input)Removes the last chip.
              ← at the input start (→ in RTL)Moves focus to the last chip's remove button.
              ← / → on a chipMove among chips and back to the input; mirrored in RTL.
              Enter, Space, Delete, Backspace on a chipRemoves it and focuses the next surviving chip, else the previous chip, else the input.

              Focus

              Focus stays in the input during option navigation and selection; the active option is conveyed by aria-activedescendant and a 2px --combobox-active-outline. The amber 3px ring (2px offset) is drawn on the whole field while the input has :focus-visible, so there is one cue, not nested rectangles. Chip remove buttons and Clear all have their own ring. Clicking an option uses mousedown prevention so the input never loses focus. Active and selected are separate cues: outline versus filled checkbox.

              Labelling

              A visible <label for> names the input (the package's inputId), or ariaLabel when no visible label exists; an unnamed field reports a development-time error. The listbox carries the same name. aria-describedby lists, in order: the error (when shown), the hint, and a visually hidden selected summary ("2 selected: Ada Lovelace, Grace Hopper"). Remove buttons are named "Remove {full label}". The toggle is "Show options" / "Hide options". Required fields set aria-required="true" and say "(required)" in the label.

              Live announcements

              The component owns one live region outside the popup (polite; assertive only for a failure). Search messages coalesce for 150 ms; queued selection messages keep their order. Results that arrive after the popup closes update silently.

              Motion

              Only the spinner moves, at --duration-loop-spin; under reduced motion it slows to 2 s per turn rather than stopping, because it reports status. The popup opens and closes without animation, and hover colours change instantly.

              Touch

              Fine pointers get 32px toggle and status buttons and 28px chip remove buttons (above the 24px minimum, with 4px gaps). Coarse pointers get 44px for every inner target. Hover styles apply only under (hover: hover). On touch keyboards the popup anchors to the input row so the visual viewport keeps the input visible.

              Content

              • Label names the set in plural, sentence case: "Learners", "Session presenters". Add "(required)" when required.
              • Placeholder is a short hint about what to type, never the label: "Name or email". Keep it under about 15 characters so it fits at 320px.
              • Hint says what to do and any limit: "Select one or more learners. Search to narrow the results." / "Choose up to 3 learners. Remove a selection to choose someone else."
              • Option detail disambiguates people with the same name (email, team, role) and states why an option is unavailable after a middle dot: "· Account inactive", "· Selection limit reached".
              • Status row: "6 of 24 learners", "24 learners available", "Loading learners…", "No results", "Learners could not be loaded. Your selections are safe." Buttons: "Retry", "Load more results".
              • Empty template guides the next step: "No learners match “Zed”. Check the spelling or search by email."
              • Error says what to do: "Select at least one learner." Not "Invalid" or "Required field".
              • Clear all is always "Clear all selections", never a bare "×".

              Drift fixed during extraction:

              • Field min-height was 40px (2.5rem) beside 44px buttons; the field is now --control-height-md (44px) like every other control.
              • Option detail text was 0.8125rem; snapped to --font-size-sm. Weight 750 on host-page eyebrows normalised to 700.
              • Spacing .1875, .375 and .625rem in the field, chips and status buttons snapped to the 4px scale.
              • Focus ring offset was 3px on the page and 2px on the field; one ring everywhere: 3px, --focus-ring-offset 2px.
              • --t-combobox-motion-duration: 0ms left the spinner static by default; the spinner now uses --duration-loop-spin and slows (not stops) under reduced motion.
              • Two disabled treatments (light background vs dashed edge); unified on the dashed edge with readable --color-fg-disabled text.
              • .sr-only implemented with clip-path here and clip elsewhere; replaced by .visually-hidden.
              • Letter-spacing 0.08em and -0.035em on host-page headings replaced by --letter-spacing-wide and --letter-spacing-tight.
              • Host page used 72rem as its container; kept only for these docs, products use --layout-container-max.
              • The popup used --t-combobox-surface; the design system raises it to --color-bg-surface-raised so it separates from the field in the dark theme.
