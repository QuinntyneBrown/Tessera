Textarea

A multi-line input for answers that run longer than a line: assignment instructions, feedback to a learner, a lesson summary. It starts at two lines and grows with what people type.

WCAG 2.2 AAStatus: stableNative <textarea>

Overview

Use a textarea when the answer may need more than one line or a line break: instructions for an assignment, written feedback, a note attached to a session in "Lecture hall A". The box size tells people how much you expect, so it starts at two lines and grows as they type instead of hiding text behind a scrollbar.

Use a text field for anything that fits on one line (a title, an email). A textarea is plain text only; rich text (headings, links, lists) needs an editor component, which Tessera does not provide. It always sits in a form field with a visible label.

Anatomy

  1. LabelFrom the form field: <label for>, always visible.
  2. Text area16px --text-body at 1.5 line height, 8px × 12px padding. Starts at 88px (two field heights), then grows with content.
  3. Container and resize handle1px --color-border-strong, --radius-md. Vertical resize only, for browsers without auto-grow.
  4. Counter (optional).field__counter at the end of the row below, tabular figures.

Variants

There is one textarea. It auto-grows by default (field-sizing: content); add a counter only when there is a real limit.

Auto-grow

Three lines of content: the box is three lines tall. Empty: two lines. Type into either to see it grow.
HTML
<div class="field">
  <label class="field__label" for="instructions">Assignment instructions</label>
  <textarea class="textarea" id="instructions"></textarea>
</div>

Where field-sizing is not supported, the textarea keeps its two-line minimum and the vertical resize handle; content scrolls inside it. Cap very long answers with a max-block-size on the instance (for example 20 lines) so the submit button stays reachable; past the cap the box scrolls.

Sizes

One size. Height is set by content, not by a size class: the minimum is two field heights (calc(2 * var(--control-height-md)), 88px, about two lines plus padding), and text is always 16px so mobile browsers do not zoom. Use the rows attribute (minimum 2) only to raise the starting height when long answers are expected.

Larger starting height signals that a longer answer is welcome.

Both themes

Enter a lesson summary.

Enter a lesson summary.

  • Invalid: 2px --color-danger-solid border plus the form field's icon and message.
  • Read-only: sunken fill, quiet border; still focusable, so a screen reader can read every line and people can copy it. Use it for instructions people must see but cannot change.
  • Disabled: dashed edge, readable text, skipped by Tab, not submitted.

Responsive behaviour

  • Full width of its field at every breakpoint; min-width: 0 lets it shrink to a 320px column.
  • Long words and URLs wrap inside the box; text never scrolls horizontally.
  • Auto-grow means 200% text and WCAG text spacing increase the height, never clip lines.
  • Resize is vertical only, so dragging the handle can never push the layout sideways. On touch, where the handle is hard to grab, auto-grow does the work.
  • On phones the on-screen keyboard can cover the bottom of a tall textarea; cap long instances with max-block-size so the box and the submit button stay reachable.

Theming

The textarea uses the same component tokens as the text field: --field-bg, --field-fg, --field-border and --field-height (which also sets the two-line minimum). Override them on a scope to re-skin; never restyle .textarea itself.

/* Taller default for reflection answers in one course */
.reflection-form .textarea { --field-height: var(--control-height-lg); }

In dark the surface becomes sage-900 and the border sage-300; the read-only fill drops to --palette-sage-975. Shipped equivalents: --t-colorNeutralBackground1, --t-colorNeutralForeground1, --t-colorNeutralStrokeAccessible. See theming.

Accessibility

Role and pattern

Native <textarea>, which exposes a multi-line textbox (aria-multiline is implied). No ARIA role is added. Labelling and errors follow labels or instructions and error suggestion.

Keyboard

KeyAction
Tab / Shift+TabMoves into and out of the textarea. Tab never inserts a tab character, so keyboard users are never trapped.
EnterInserts a new line. It never submits the form.
Arrows, Home / End, Ctrl+Home / EndNative caret movement by character, line and document.
EscNo effect. In a dialog, Esc closes the dialog; ask before discarding typed text.

Focus

The shared ring (3px --color-focus-ring, 2px offset) on :focus-visible. Because the box grows, the caret line stays in view; browsers scroll the page to keep it visible, and no sticky footer may cover it (WCAG 2.4.11).

Labelling

  • A visible <label for>; the placeholder is a prompt at most.
  • aria-describedby lists error, hint and counter, in that order.
  • The counter text is static in aria-describedby; a separate visually hidden aria-live="polite" region announces "10 characters left" and "5 characters too many" when those thresholds are crossed, debounced by about a second, never on every keystroke.

Motion

Growth is immediate; it is never animated, so the text under the caret does not slide. The border colour transitions over --duration-fast, zeroed under reduced motion.

Touch

The minimum 88px height is a large target. The label also focuses the textarea. The resize handle is a convenience, not the only way to see more text, because the box grows on its own (no drag required, WCAG 2.5.7).

Content

  • Label says what to write and for whom: "Feedback for Grace Hopper", "Assignment instructions".
  • The hint says who will see it or what makes a good answer: "Only Grace and course instructors see this."
  • State limits up front in the counter ("0 of 500 characters"), and in characters, not words, so the count is unambiguous.
  • Over the limit, say by how much and what to do: "Lesson summary must be 200 characters or fewer." with "17 characters too many" in the counter.
  • Placeholders such as "What went well, and what to try next" are optional prompts; never put instructions people need there.

Derived: not present in the mocks; follows the system rules. Border, radius, fill, placeholder colour, invalid and disabled treatments are shared with the text field, itself derived from the field in the combobox mock.

Drift that applies through the shared field styles:

  • Control radii of 6px (combobox mock selects) and 7px (video mock selects) snapped to --radius-md (8px), the combobox field's radius.
  • Off-grid field padding snapped to --space-2 / --space-3.
  • Two disabled treatments unified on the dashed edge with readable --color-fg-disabled text.
  • Focus outline 2px on fields vs 3px on the page; unified on the 3px ring with a 2px offset.
