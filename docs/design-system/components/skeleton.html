Skeleton

A skeleton is a grey placeholder in the shape of content that is about to arrive: a course card, a row of learners, the picture of a live session that is still connecting. It keeps the layout steady so nothing jumps when the content lands.

WCAG 2.2 AAStatus: stablearia-hidden · container aria-busy

Overview

Use a skeleton on first load of a region whose layout is known: a list of courses, a table of learners, the video stage. It shows that content is coming and where, and avoids layout shift.

  • Use a spinner for small or unknown-shaped waits (a field lookup), and for reloading content that is already on screen.
  • Use a progress bar when progress can be measured.
  • Never use a skeleton for content that failed: replace it with an alert or an empty state.

Skeletons are a visual hint only. Assistive technology hears about loading from the container's aria-busy and from a status message, never from the grey shapes.

Anatomy

  1. RectMedia or thumbnail block; aspect-ratio from --skeleton-ratio (16 / 9 default), --radius-md.
  2. Title1.5em tall, 60% wide by default; stands in for a heading.
  3. Text lines1em tall; the last line shorter (--skeleton-width) so it reads as a paragraph.
  4. ContainerThe real component (card, row, stage) with aria-busy="true"; its padding and gaps match the loaded state.

Sizes

Skeletons take the size of what they replace. Text lines are sized in em so they match the surrounding font; widths and ratios are tuned per instance with component tokens.

PrimitiveHeightWidthTune with

.skeleton--title1.5em60%--skeleton-width
.skeleton--circle2.5rem (40px) by default; set it to the size of the avatar it replaces (2rem default, 2.75rem large)--skeleton-size
.skeleton--rectfrom ratio100%--skeleton-ratio (16 / 9)
Circles at 32 / 40 / 56px; text lines at 14px, 16px and a 24px heading.

States

Skeletons are not interactive: hover, focus, active and disabled do not apply, and nothing inside a busy container is focusable. Their states are shimmering (default), static (reduced motion or forced colours) and replaced (content arrived, or an error or empty state took over).

Timing

  • Show skeletons immediately on first load (they replace empty space, so there is no flash risk); swap all at once when the data arrives, not piece by piece.
  • After about 10 s with no data, add a status line ("Still loading courses…"); after a timeout, replace with an alert and Retry.

Responsive behaviour

  • Composed skeletons use the same layout classes as the loaded component, so they reflow identically: card grids drop columns, rows stay rows.
  • Rect skeletons keep their aspect ratio at every width; text lines are percentages of their container.
  • Show fewer skeleton rows on short viewports (enough to fill the first screen).
  • At 200% text, em-based lines grow with the text they stand for.

Theming

The skeleton fill is --color-skeleton (sage-100 in light, sage-700 in dark) with a highlight band of --color-bg-subtle sweeping across it. Shapes take --radius-sm (text), --radius-md (rect) and --radius-full (circle). In forced-colours mode --color-skeleton maps to Canvas so placeholders vanish rather than painting arbitrary blocks. In the shipped video player the same value is --t-video-player-skeleton; see theming.

/* A host with a darker canvas raises skeleton contrast locally */
.catalogue { --color-skeleton: var(--palette-sage-300); }

Accessibility

Role and pattern

Every skeleton shape is aria-hidden="true" (or sits inside an aria-hidden wrapper). The region it fills sets aria-busy="true" until the content is in place, then removes it. A polite role="status" message ("Loading courses", "Connecting to Lecture hall A.") reports the wait once; the arrival is reported only if it is not obvious ("12 courses loaded"). See Understanding 4.1.3 Status Messages.

Keyboard

KeyAction
(none)Skeletons are never focusable. Controls that will appear with the content are not rendered until then, so Tab does not land on placeholders.

Focus

When content replaces a skeleton, focus is not moved. If focus was on a control that the reload removed, it moves to the region's heading.

Labelling

The ghost title on the video stage is aria-hidden; the session name is already the player region's label ("Video player: Lecture hall A"). "Connecting…" is real text in the player's status flow.

Contrast

Skeleton on surface (decorative)
"Connecting…" on skeleton
Text on skeleton stage

Skeleton shapes are decorative placeholders and exempt from 1.4.11; they need only be distinguishable from the surface. Any real text drawn on a skeleton meets 4.5:1.

Motion

The shimmer sweeps once per --duration-loop-shimmer (2.2 s), a slow, low-contrast gradient with no flashing. Under prefers-reduced-motion the animation is removed and the shapes stay a flat --color-skeleton; unlike a spinner, a static skeleton still reads as "loading" because of its shape.

Touch

Not a target. Taps on a skeleton do nothing; do not attach the future content's click handler to its placeholder.

Content

  • Skeletons have no words, except on media where the session name and "Connecting…" orient the viewer.
  • The hidden status names the content: "Loading courses", "Loading learners", "Connecting to Lecture hall A."
  • Mirror the real layout's proportions: line counts and widths close to typical content, not a single full-width bar.
