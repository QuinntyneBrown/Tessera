Radio group

A radio group asks for exactly one choice from a short list that stays visible: how a course decides completion, which format a session uses, whether an assignment is required.

Overview

Use a radio group when a person must pick one option, there are two to about seven options, and comparing them side by side helps. Every option is visible, so nobody has to open anything to learn what is possible.

  • More than about seven options, or a long familiar list (countries, time zones): use a select.
  • A large, searched set (learners, courses): use the combobox.
  • Several choices allowed: use checkboxes.
  • A single on/off setting that applies at once: use a switch. A radio group's choice is submitted with its form.
  • Switching a view ("Outline" / "Transcript"): use tabs or a segmented button group, not radios.

Anatomy

  1. Legend<legend> inside .fieldset: bold 16px. It is the group's accessible name and is read before each option.
  2. Group hint (optional).field__hint, linked to the fieldset with aria-describedby.
  3. RadioNative input, 20px, accent-color: --color-accent, aligned to the first line of the label.
  4. Label.check__text, body 16px. The wrapping <label class="check"> makes the whole 44px row the target.
  5. Description (optional).check__description, 14px muted, part of the label, so it is announced with the option.

Variants

The layout changes; the behaviour does not. Choose by label length and how much each option needs explaining.

Vertical (default)

Completion rule
One option per row; the easiest layout to scan and the only one that works for long labels.

Card

Assignment type

Sizes

One size. Radios are 20px inside a 44px row (--control-height-md); the row, not the dot, is the target, so a smaller size would fail the comfortable target and a larger one adds nothing.

States

Native radios draw their own hover and pressed feedback; the system adds the focus ring, the invalid outline and the readable disabled text. Focus is forced here with data-state="focus"; hover and active columns show the native control, which differs slightly per browser.

Both themes

Assignment type
Assignment type
  • Checked is the native filled dot in --color-accent; card radios also get the accent border, an inset 1px accent ring and --color-accent-subtle fill. The dot remains the non-colour cue.
  • Invalid never relies on colour alone: the message with its icon says what to do.
  • Read-only does not exist for native radios; show the chosen value as text (a description list) instead of a frozen group.

Responsive behaviour

  • Vertical groups and cards reflow naturally down to 320px; labels and descriptions wrap, never truncate.
  • Horizontal groups wrap onto extra rows (24px column gap). If a label would wrap inside a horizontal group at 320px or at 200% text, use the vertical layout instead.
  • Cards are full width on phones. From --layout-breakpoint-md (768px) up, short card sets may sit side by side in .grid--auto; keep them in a single column when descriptions run longer than one line.
  • Every row is at least 44px tall at every width, so the target never shrinks on touch.

Theming

Radios have no component tokens: the native control paints itself with accent-color: var(--color-accent), so changing the accent re-themes every radio. Cards read --color-border-strong, --color-accent and --color-accent-subtle. In the dark theme the accent lightens to teal-300 and the selected card fill becomes sage-800, keeping text above 4.5:1. In forced-colours mode the browser draws the radio in system colours and the card keeps its 1px border.

/* A host area with its own accent re-themes radios through the semantic token */
.learner-portal { --color-accent: var(--palette-teal-700); }

Accessibility

Role and pattern

Native <input type="radio"> elements sharing one name, grouped in a <fieldset> whose <legend> names the group. This gives the WAI-ARIA APG Radio Group pattern behaviour for free; do not rebuild it with role="radio".

Keyboard

KeyAction
Tab / Shift+TabMoves into the group onto the checked radio (or the first radio when none is checked), and out of the group. The group is one Tab stop.
↓ / →Moves to and checks the next radio, wrapping to the first. In RTL, ← moves forward.
↑ / ←Moves to and checks the previous radio, wrapping to the last.
SpaceChecks the focused radio if it is not already checked.
EnterSubmits the surrounding form (native).

Focus

The shared 3px amber ring with 2px offset is drawn around the radio itself on :focus-visible. On cards it is still drawn on the radio, so the selected card's accent edge and the focus ring never merge. Disabled radios are skipped by arrow keys.

Labelling

Every radio sits inside its <label class="check">, so the label text and description are its name. The legend names the group; screen readers announce "Completion rule, group" before the first option. Group hints and errors are linked to the fieldset with aria-describedby; required groups say "(required)" in the legend.

Motion

None. The dot appears instantly; cards change colour without a transition.

Touch

The whole 44px label row (or the whole card) is the target, not the 20px dot. Vertical rows have no gap, but each is 44px tall; horizontal options are 24px apart.

Content

  • The legend is a short noun phrase or question: "Completion rule", "How should learners attend?" Add "(required)" when required.
  • Option labels are parallel, sentence case and short: "In person", "Online", "Hybrid". Do not start every option with the same word.
  • Put the safest or most common option first and check it by default when a default is reasonable. Leave the group unchecked only when choosing is the point, and then validate it.
  • Include "None" or "Not applicable" if it is a valid answer, rather than letting people skip the group.
  • Descriptions explain consequences, not the label again: "Learners see a due date and get reminders until they finish."
  • Error messages say what to do: "Choose how the course is completed."
