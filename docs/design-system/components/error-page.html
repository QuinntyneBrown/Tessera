Error page

An error page takes the place of a page that cannot be shown: a course that no longer exists, a report the person may not see, a server failure, a lost connection. It keeps the product around it, says plainly what happened, and offers one way forward.

Overview

Use an error page only when the main content of a route cannot be rendered at all. Keep the top bar and navigation wherever the shell itself loaded, so the person can go somewhere else without the Back button.

  • 404 Not found: the course, lesson or session link points nowhere.
  • 403 No access: the content exists but this person's role cannot open it.
  • 500 Something went wrong: the server failed; show a reference id for support.
  • Offline: the browser has no connection; retry when it returns.
  • Maintenance: the LMS is deliberately unavailable for a known period.

When only part of a page fails, use an alert or an error empty state in that region instead. Inside a player (SCORM or video), errors stay inside the player as an alert, never take over the page. See the empty and error states pattern.

Anatomy

  1. Code (eyebrow)--text-overline, uppercase, wide tracking, accent colour. The status in human form ("Error 500", "Offline"); supports, never replaces, the title.
  2. TitleThe page's <h1>, --text-h1 with tight tracking. What happened, in plain words.
  3. BodyMuted, up to --layout-measure. What it means for the person, then what to do.
  4. Reference (500 only)Monospace --text-code. Something to quote to support; selectable, never the only detail.
  5. ActionsOne primary recovery ("Try again") and one way out ("Go to My learning"); 24px above, 12px apart.

Examples are shown at reduced height; in product .error-page takes at least 60% of the viewport height and centres its content in the main area.

Error pages fill the main content area; they have one size.

  • Offline → online: listen for the browser's online event and reload automatically; announce "Back online. Reloading." politely.
  • Try again fails again: keep the page, update the reference id, and say "Still not working. Contact support with reference …".

Responsive behaviour

  • Content centres in the main area with --layout-margin inline padding; body text stops at --layout-measure (60ch).
  • The title stays --text-h1 (32px, rem-based so it follows zoom) and wraps with balanced lines; it never truncates.
  • Actions wrap onto a new line when they no longer fit side by side, primary first; each keeps its 44px height.
  • min-height: 60dvh uses dynamic viewport units so mobile browser chrome does not push actions off screen.
  • The reference id wraps at its separator; it never forces horizontal scroll at 320px or 400% zoom.

Theming

The error page reads only semantic tokens: --color-fg-accent (code), --color-fg-default (title), --color-fg-muted (body, reference), on the page's --color-bg-canvas. It deliberately uses the accent, not danger red, for the code: a missing page is not an alarm. There are no component tokens; a host brand changes the accent and the page follows. See theming.

Accessibility

Role and pattern

A normal page: the error title is the only <h1> inside <main>, landmarks and the skip link stay. The document <title> starts with the error ("Course not found — Tessera LMS") so it is the first thing announced. No live region: the person arrived by navigation. Serve the real HTTP status (404, 403, 500, 503) so assistive tools and crawlers agree with the page. See Understanding 2.4.2 Page Titled.

Keyboard

KeyAction
TabSkip link, shell navigation, then the page actions in order.
Enter / SpaceFollows a link (Enter) or activates a button.

Focus

On a client-side route change to an error, move focus to the <h1> (tabindex="-1"), as on any route change; on a full page load the browser starts at the top. After "Try again" succeeds, the real page loads and focus follows the route-change rule.

Labelling

The code eyebrow is plain text, read before the title; keep it short so it does not delay the message. "Copy reference" announces "Reference copied" politely after copying.

Contrast

Motion

None. No animated illustrations, no auto-redirect countdowns; an automatic redirect would move people before they read the page (WCAG 2.2.1).

Touch

Actions are 44px buttons or button-styled links, 12px apart in both directions when they wrap.

Content

Tone follows the video player's errors: direct, specific, no blame, a next step in the same breath ("You don’t have access to this stream. Sign in again or ask the organiser.").

  • Lead with what the person cares about (their course, their progress), not the HTTP status.
  • Never show stack traces, exception names or raw codec strings; put technical detail behind the reference id.
  • No humour, no "Oops". A learner who cannot reach mandatory training is not amused.
