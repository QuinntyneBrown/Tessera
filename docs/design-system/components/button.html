Button

Buttons let learners and administrators take an action: continue a lesson, retry a connection, preview an assignment. One primary button per view says what matters most.

Overview

Use a button when activating it changes something: it continues, retries, submits, opens a dialog or starts playback. Use a link when it only takes the person somewhere. Use a menu when one trigger offers several actions. Media transport controls (play, mute, captions) are video player controls, not general buttons.

  • Primary is the one action the view exists for ("Continue", "Preview assignment", "Retry"). Never two per view.
  • Secondary (the default look) is for every other action ("Previous", "Exit course").
  • Ghost sits inside dense surfaces: toolbars, table rows, popup status rows, dialog close buttons.
  • Link looks like a link but is a button; use it for low-emphasis actions next to text, such as "Clear all selections" under the combobox.
  • Danger is for destructive actions and only appears inside a confirmation step.

Anatomy

  1. Icon (optional)1.25em, inherits the label colour, aria-hidden="true". Leading for direction-neutral actions, trailing for "next".
  2. Label--text-label: bold 14px. A verb phrase in sentence case; it is the accessible name.
  3. Container44px tall (--control-height-md), --radius-md corners, 1px border, 16px inline padding.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves on this view.

Emphasis from highest to lowest; danger is reserved for destructive confirmations.
HTML
<button class="btn btn--primary" type="button">Continue</button>
<button class="btn" type="button">Previous</button>
<button class="btn btn--ghost" type="button">Load more</button>
<button class="btn btn--link" type="button">Clear all selections</button>
<button class="btn btn--danger" type="button">Remove learner</button>

With icons and icon-only

Icon-only buttons carry aria-label and a tooltip; the icon itself is aria-hidden.

Sizes

Medium (44px) is the default; every mock uses it, and it meets the comfortable touch target. Small lives inside rows and popups where the row is also a target (the combobox status row's "Retry"); large is for a single hero action.

Heights: --control-height-sm/md/lg; padding: --space-3/4/6; font: --font-size-sm (sm, md) and --font-size-md (lg).

States

Every variant has the same six states. Pointer and focus states are forced here with data-state so they can be reviewed without a mouse; products get them from :hover, :focus-visible, :active, :disabled / aria-disabled and aria-busy.

Both themes

  • Disabled keeps the label readable (--color-fg-disabled passes 4.5:1) and switches the edge to dashed, as in the combobox and SCORM mocks. Disabled is never shown by fading alone.
  • Unavailable but discoverable: when a learner needs to find the control and learn why it cannot be used (SCORM "Continue" before the lesson is complete), use aria-disabled="true" instead of disabled so it stays focusable, and say why next to it (.content-player__reason).
  • Loading keeps the width and name, hides the label, shows a spinner, sets aria-busy="true" and ignores further clicks. Wrap the label in a <span> so it can be hidden.
  • Pressed (toggle buttons) uses aria-pressed; see button group.

Responsive behaviour

  • Button rows (.content-player__actions, .form__actions, dialog footers) wrap rather than shrink. Below --layout-breakpoint-md (768px) form actions stack full width with the primary on top.
  • Below --layout-breakpoint-sm (640px) dialog footers become a sticky sheet footer and buttons share the row equally.
  • Labels never truncate; a label that wraps at 320px is too long. Shorten the verb phrase instead. With 200% text the button grows taller; it never clips.
  • Medium and large already meet 44px on touch; small buttons are only used where the row around them is also a target, with 8px between neighbours.

Theming

The button reads semantic tokens through six component tokens (--btn-bg, --btn-bg-hover, --btn-bg-active, --btn-fg, --btn-border, --btn-height) that each variant overrides. A theme changes semantic tokens; a host re-skin overrides component tokens; neither touches the component CSS.

/* An LMS host re-skins primary buttons without touching .btn */
.learning-area .btn--primary { --btn-bg: var(--color-accent); --btn-fg: var(--color-fg-on-accent); }

In the dark theme the accent lightens to --palette-teal-300 and the label flips to --color-fg-on-accent (sage-900), so the pair stays above 8:1; danger does the same with the red ramp. In the shipped packages the same decisions are --t-colorBrandBackground and --t-colorNeutralForegroundOnBrand; see theming.

Accessibility

Role and pattern

Native <button type="button"> (or type="submit" inside a form), following the WAI-ARIA APG Button pattern. A link styled as a button is still an <a href>; never a <div> with a click handler. No ARIA role is needed.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order. aria-disabled buttons stay in the sequence; disabled ones leave it.
Enter, SpaceActivates the button. Space activates on key up, so a mis-press can be cancelled by moving away.
EscNo effect on the button itself; a loading button cannot be cancelled with Esc, so offer a separate Cancel when an action is long.

Focus

The shared ring (3px --color-focus-ring, 2px offset) appears on :focus-visible only. The ring is amber, not the brand teal, so it stays distinct from a primary button's fill and from selected states. Within media controls it uses --color-media-focus-ring.

Labelling

The visible label is the accessible name. Icon-only buttons set aria-label with the verb and object ("Remove Ada Lovelace", "Show outline") and show a tooltip on hover and focus. Loading buttons keep their name and add aria-busy="true"; progress text ("Saving…") is announced by the component's live region, not by the button.

Motion

Background, border and colour transition over --duration-fast (150 ms); active translates 1px. Under prefers-reduced-motion the token is zeroed and the translate removed. The loading spinner keeps turning, slowed to 2 s per revolution, because it reports status.

Touch

Medium (44px) and large (48px) meet the 44px comfortable target; small (32px) still exceeds the 24px minimum and is only used where its row is also tappable. Hover styles apply only under (hover: hover), so a tap never leaves a sticky hover.

Content

  • Labels are verb phrases in sentence case: "Continue", "Retry", "Preview assignment", "Exit course". Never "OK", "Submit", "Click here".
  • Name the object when context does not: "Remove Ada Lovelace" on an icon-only chip button, "Clear all selections" rather than "Clear".
  • Destructive labels name the loss: "Remove 3 learners", not "Confirm".
  • Keep labels to three words where possible; a label that wraps at 320px is too long.
  • Explain unavailable actions in text next to them ("Complete this lesson to continue"), not only with a disabled look.

Drift fixed during extraction:

  • Radius was 7px (SCORM, video) and 6px (combobox); normalised to --radius-md (8px), matching @tessera/theme borderRadiusMedium.
  • Label weight 750 (SCORM, video) and 700 (combobox); normalised to 700, since 750 renders as 700 in every fallback font.
  • Label size 0.87rem and 0.875rem; normalised to --font-size-sm.
  • SCORM secondary border #7f978d and hover #f1f6f3 were one-off values; replaced with --color-border-strong and --color-bg-subtle.
  • Two disabled treatments (SCORM: light border; combobox: dashed border); unified on the dashed edge with readable text.
