Component · Data display

Table

Tables let administrators compare learners across the same columns: who has finished a course, who is behind, who has not started. They are for scanning and acting on records, not for laying out a page.

Overview

Use a table when every record has the same attributes and people need to compare them down a column: learner progress in a course, scores across an assignment, attendance across sessions. Use a list when records have one or two lines of text and no shared columns, and a description list for the attributes of a single record.

  • Default is the comfortable density for review screens ("Learner progress").
  • Dense fits more rows on reporting screens where people scan numbers.
  • Sortable columns use a .table__sort button in the header and aria-sort on the sorted column.
  • Selectable rows add a checkbox column; selecting one or more reveals the bulk bar (.table__bulk) with actions for the whole selection.
  • Row actions (.table__actions) sit in the last column: ghost icon buttons with a named target.

The table is a static document table, not a spreadsheet: there is no cell-by-cell arrow navigation. If a product needs editable cells, that is a separate grid component with the APG Grid pattern.

Anatomy

  1. Caption<caption> in --text-h4. Names the table for screen readers; it can be visually hidden when a heading above says the same.
  2. Header row<th scope="col"> on --color-bg-surface-sunken, --text-label in --color-fg-muted, no wrapping, sticky to the top of .table-wrap.
  3. Sort button.table__sort: the header text plus a 16px arrow; the arrow is at 50% opacity until the column is sorted. At least 24px tall.
  4. Body cell--space-3 × --space-4 padding, --text-body-sm, hairline --color-border-default divider.
  5. Numeric cell.num: end-aligned, tabular figures, so percentages line up.
  6. Row actions.table__actions: end-aligned ghost icon buttons, each named for its row.
  7. Selected rowaria-selected="true" fills the row with --color-accent-subtle; the row checkbox carries the state for assistive technology.

The container .table-wrap draws the border and --radius-lg corners and owns horizontal scrolling. The bulk bar .table__bulk is its first child when rows are selected.

  • Row hover fills with --color-bg-subtle, only under (hover: hover). It is a reading aid, not a state; nothing is announced.
  • Row selected fills with --color-accent-subtle and the row checkbox is checked. In the dark theme --color-accent-subtle and --color-bg-subtle resolve to the same sage-800, so a hovered and a selected row look alike there: the checked checkbox is the cue that must always be present.
  • Disabled row: a row that cannot be selected (an inactive account, as in the combobox's "Account inactive" option) keeps readable text and a disabled checkbox, and says why in a cell.

Responsive behaviour

  • The page never scrolls sideways. A table wider than its column scrolls inside .table-wrap (overflow-x: auto), which is the one two-dimensional scroll WCAG 1.4.10 allows for data tables.
  • A scrolling wrapper is a keyboard stop: give it tabindex="0", role="region" and aria-labelledby pointing at the caption, so keyboard users can scroll it with the arrow keys and screen reader users hear its name.
  • Header cells never wrap (white-space: nowrap); body cells wrap. At 320px and with 200% text, keep the learner name column first so the row header is always visible at the start of the scroll.
  • The bulk bar wraps its actions onto a second line below 40rem rather than overflowing.
  • Below --layout-breakpoint-md, drop low-value columns (Score, Last active) from the markup only if the same data is reachable from the learner's detail page; never hide data with CSS alone.
  • Sticky headers stick inside .table-wrap when it has a height limit; never use a page-level sticky header that could cover a focused row (WCAG 2.4.11).

Theming

The table reads semantic tokens directly: --color-bg-surface (body), --color-bg-surface-sunken (header), --color-border-default (row dividers and frame), --color-bg-subtle (hover), --color-accent-subtle (selected row and bulk bar). It has no component tokens yet; re-skin it by overriding those semantic tokens on a wrapper.

/* A reporting page that wants a quieter header */
.report .table-wrap { --color-bg-surface-sunken: var(--color-bg-surface); }

In the dark theme the frame and dividers become sage-700, the header sage-975, and the selected fill sage-800. In the shipped packages the same decisions map to --t-colorNeutralBackground1, --t-colorNeutralBackground2 and --t-colorNeutralStroke1; see theming.

Accessibility

Role and pattern

Native <table> with <caption>, <th scope="col"> and a row header <th scope="row">, following the WAI-ARIA APG Table pattern and its sortable table example. Do not add role="grid": that promises arrow-key cell navigation the table does not have. aria-selected on a <tr> is the styling hook; screen readers do not announce it in a plain table, so the row checkbox is what communicates selection.

Keyboard

KeyAction
Tab / Shift+TabMoves through the interactive parts in reading order: bulk bar actions, header checkbox, sort buttons, then each row's checkbox, links and row actions. Cells without controls are not stops.
Enter, Space on a sort buttonSorts by that column; a second press reverses the order. Focus stays on the button.
Space on a checkboxSelects or clears the row. On the header checkbox, selects all rows on this page, or clears them when all are selected.
Enter, Space on a row actionRuns the action, or opens its menu (then arrows move, Esc closes and returns focus to the button).
← → ↑ ↓When the scrolling .table-wrap region has focus, scrolls it. Screen readers use their own table commands to move between cells.

Focus

The shared amber ring (3px --color-focus-ring, 2px offset) on sort buttons, checkboxes, links, row actions and the scroll region. After sorting, focus stays on the sort button. After a bulk action removes rows, focus moves to the bulk bar's status or, when nothing is left selected, to the header checkbox. Never let a sticky header cover the focused row.

Labelling

The caption names the table and says it is sortable ("Column headers with buttons are sortable"). Each row checkbox is named "Select <learner>"; the header checkbox "Select all learners". Row action buttons name the action and the learner ("Message Ada Lovelace"). The actions column has a visually hidden header ("Actions"). Status cells use a badge with text, never colour alone. Sorting and loading are announced through one polite status: "Sorted by progress, highest first", "Loading learners…", "20 learners".

Row dividers (--color-border-default) are decorative and exempt from 1.4.11: rows are also separated by their content and the row header.

Motion

Skeleton rows shimmer over --duration-loop-shimmer; under prefers-reduced-motion the shimmer stops and the skeleton stays as a flat --color-skeleton block. Sorting re-renders rows instantly; never animate row reordering.

Touch

Row checkboxes sit in a 44px .check label, row actions are 32px with 4px between them inside a row, sort buttons are at least 24px tall. Hover fills apply only under (hover: hover). Horizontal scrolling inside .table-wrap works with a single-finger swipe; nothing depends on a drag.

Content

  • Captions say what the rows are and for what: "Learner progress: Workplace safety essentials".
  • Column headers are short nouns in sentence case: "Learner", "Status", "Progress", "Last active". Put units in the header ("Minutes watched"), not in every cell.
  • Numbers end-align with .num; percentages have no space ("64%"). Dates use "8 Oct 2026". A missing value is an en dash "–", never blank and never "N/A".
  • Status cells use the same four words everywhere: "Completed", "In progress", "Not started", "Overdue".
  • Bulk bar counts name the thing: "2 learners selected". Bulk actions are verbs: "Send reminder", "Extend due date". Destructive bulk actions ("Remove 2 learners") go through a dialog.
  • Empty states say why there is nothing and what to do: "No learners assigned yet" + "Assign learners". Errors say what failed, that nothing was lost, and offer Retry.
