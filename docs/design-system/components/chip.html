Chip

Chips are compact values people can see at a glance and act on: the learners already chosen in the combobox, the status filters above a table, the topics a course is tagged with.

Overview

There are three kinds of chip, and they behave differently:

  • Input chips (.chip.chip--removable) show values someone has chosen and let them remove one. The chip is not interactive; its remove button is. They come from the combobox, where each selected learner becomes a chip.
  • Filter chips (.chip--filter) are toggle buttons with aria-pressed that narrow a table or list: "Overdue", "In progress".
  • Static chips (.chip--static) are read-only tags: course topics, a session's room.

Use a badge for a status nobody can change, a button group when exactly one option must be chosen, and a checkbox group inside forms where filters are submitted rather than applied live.

Anatomy

  1. Container.chip: 32px tall (--control-height-sm), --radius-sm, hairline --color-border-strong, --color-accent-subtle fill. Filter chips are 44px pills.
  2. Label.chip__label: --text-body-sm, one line, ellipsis when it overflows, full text in a tooltip.
  3. Remove button (input chips).chip__remove: 28px square native button with a 16px × icon and aria-label="Remove <name>". The only focus stop in the chip.
  4. Chip list.chip-list: a <ul> that wraps with a --space-1 gap, named for what it holds ("Selected values").

The label truncates with an ellipsis; the full text appears in a tooltip on pointer hover over the chip and on focus of its remove button, stays while hovered, and closes with Esc. The remove button's name already holds the full text, so nothing is lost for screen readers.

Small 24px (.chip--sm, --text-caption) · medium 32px (default, --text-body-sm). Filter chips are always 44px.
  • Medium (32px) is the default and what the combobox uses inside its 44px field.
  • Small (24px) is for static tags in dense rows and for read-only summaries. Avoid small removable chips on touch screens: the remove button stays 28px but the chip around it gets tight.
  • Filter chips are 44px (--control-height-md) because the whole chip is the target.

  • Focus rings only the remove button on input chips, exactly as in the combobox: the field shows its own ring while the input has focus, and a focused remove button shows only its own.

  • Pressed filter chips use aria-pressed="true": accent edge, accent-subtle fill, --color-fg-accent text and a check icon.
  • Active has no separate look; removal or toggling is the feedback.

In the dark theme --color-accent-subtle and --color-bg-subtle are both sage-800, so input and static chips share a fill; they differ by the remove button. A pressed filter chip still differs from an unpressed one by its accent edge, accent text and check icon.

Responsive behaviour

  • .chip-list wraps onto as many rows as needed; it never scrolls sideways.
  • A chip never exceeds its container (max-width: 100%); the label truncates with an ellipsis and the full text is in the tooltip and the remove button's name.
  • Inside the combobox the chip list is capped at 8rem tall (--combobox-chip-list-max-height) and scrolls vertically; with 200 selections the input stays reachable below it.
  • Filter chip rows wrap at 320px; with many filters, collapse the rest behind a "More filters" menu rather than a second scrolling row.
  • In right-to-left layouts the remove button sits at the start edge and the chip arrow keys mirror.

Theming

Two component tokens: --chip-bg and --chip-border. Variants and states set them (--chip-bg is --color-accent-subtle for input chips, --color-bg-subtle for static, --color-bg-surface for filter; pressed filter chips switch --chip-border to --color-accent). The combobox passes its own --combobox-chip-bg through.

/* A host that wants neutral selected-value chips */
.assign-form .chip--removable { --chip-bg: var(--color-bg-subtle); }

In the shipped combobox the same decision is --t-combobox-chip-bg, defaulting to --t-colorNeutralBackground2 (and Canvas in forced colours); see theming.

Accessibility

Role and pattern

Input and static chips are list items in a named <ul>; the remove button is a native <button> following the APG Button pattern. Inside the combobox, the chips sit beside an input that follows the APG Combobox pattern. Filter chips are toggle buttons (aria-pressed) in a role="group" with a name. No chip uses role="option" or a grid role.

Keyboard

KeyAction
Tab / Shift+TabReaches each remove button and each filter chip in order. Static chips are skipped.
Backspace in the empty combobox inputRemoves the last chip. Focus stays in the input.
← at the start of the combobox inputMoves focus to the last chip's remove button.
← / → on a remove buttonMoves to the previous / next chip's remove button; → on the last chip returns to the input. Mirrored in right-to-left layouts.
Enter, Space, Delete, Backspace on a remove buttonRemoves that chip. Focus moves to the next chip's remove button, or the previous one when the last chip was removed, or to the input when no chips are left.
EscCloses a long-label tooltip first; inside the combobox, then closes the popup, then clears the query.
Enter, Space on a filter chipToggles aria-pressed and applies the filter. Focus stays on the chip.

Focus

Only the remove button is focusable on an input chip, and only it shows the amber ring (3px --color-focus-ring, 2px offset). The chip body never shows a ring of its own. Filter chips show the ring around the whole pill. Focus never disappears on removal: it moves to the next chip, else the previous one, else the input.

Labelling

The chip list is named for its content ("Selected values"). Each remove button is named "Remove <name>" with the full, untruncated name. Removal is announced through the combobox host's polite live region ("Ada Lovelace removed."). Filter groups are named ("Filter learners by status"); a pressed chip is announced "Overdue, toggle button, pressed". The × icon and the check icon are aria-hidden.

Motion

Chips appear and disappear without animation, so a removed learner's chip is gone the moment the announcement says so. Hover fills change instantly. Nothing to reduce under prefers-reduced-motion.

Touch

Remove buttons are 28px square, above the 24px minimum, with 4px between chips; on touch the whole field around the combobox chips is also a target for the input. Filter chips are 44px. The tooltip is also reachable without hover, by focusing the remove button.

Content

  • Input chips show the value exactly as it was chosen: the learner's full name. Never abbreviate in the label; let it truncate and show the full text in the tooltip.
  • Remove buttons are "Remove <name>", never "Delete" or a bare "×".
  • Filter chips are one or two words in sentence case, using the same vocabulary as the badges they filter: "Not started", "In progress", "Overdue", "Completed".
  • Static chips are nouns: "Communication", "Feedback".
  • Pair a chip list with a count and a way to undo bulk changes: "2 learners selected" and "Clear all selections" (a text button below the field, not a × in the field).
