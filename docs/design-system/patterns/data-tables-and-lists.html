Pattern

Data tables and lists

Administrators scan, sort and act on collections: the learners on an assignment, the activities in a course, the results of a search. Tables compare values across columns; lists show one thing per row; both page in predictable steps.

WCAG 2.2 AAStatus: stableComposes: table, list, checkbox, chip, badge, pagination, combobox, empty state

Overview

A collection view is a toolbar (search and filters), an optional bulk-action bar, the collection itself, and a way to get more. Every part reports its result in words: how many match, how many are selected, how many more were loaded.

  • Table (table) when people compare values across rows: status, progress, due date per learner.
  • List (list) when each row is one item with a title and a line of detail: sessions, activities, search results.
  • Listbox in a popup (combobox) when the collection exists to pick from. It pages six at a time by scrolling or "Load more results".

Density

Default rows (.table: 12px × 16px cell padding) for everything people act on. Dense rows (.table--dense: 8px × 12px) only for read-only reports where scanning many rows matters more than targets. A row that contains controls keeps 44px targets at either density.

Toolbar, bulk bar (only while something is selected), table, pagination. The result count sits next to the filters so a filter change and its effect are read together.

Sorting

  • Sortable headers contain a .table__sort button; the sorted column's <th> carries aria-sort="ascending|descending", others none. One column at a time.
  • First press sorts ascending (A–Z, oldest, lowest); the second reverses. Default sort is stated in the caption.
  • After sorting, announce "Sorted by due date, ascending" in the polite status region; focus stays on the header button.

Filtering

  • Search filters as the person types, debounced (300 ms in the combobox mock). Filter chips are toggle buttons (aria-pressed) inside a labelled group.
  • The count updates in a polite role="status" region: "4 of 48 learners match." Never move focus on filter changes.
  • A filter that matches nothing shows the empty state with "Clear filters"; see empty and error states.

Selection and bulk actions

  • One checkbox per row, named "Select learner name". The header checkbox selects the current page and is indeterminate when some are selected (set indeterminate from script).
  • Selected rows tint with --color-accent-subtle; the checkbox, not the tint, carries the state.
  • The bulk bar (.table__bulk) appears above the table with the count first: "2 learners selected". Destructive bulk actions open a confirmation that repeats the count ("Remove 2 learners?").
  • Selection survives sorting and paging; it is cleared only by "Clear selection", a completed bulk action, or a filter that hides the rows (say so: "2 selected learners are hidden by filters").

Responsive behaviour

The page never scrolls sideways. Pick one strategy per collection:

  • Stack to a list (preferred for up to four data columns): below --layout-breakpoint-md (768px) render each row as a .list__item: name as the title, status and progress as the meta line, the row action in the trail. Selection checkboxes move to the start of each item.
  • Scroll inside the table (wide reports only): .table-wrap scrolls horizontally on its own, is a focusable labelled region (role="region", tabindex="0") so keyboard users can scroll it, and the header stays sticky. This is the data-table exception in WCAG 1.4.10 Reflow; the rest of the page still reflows.
  • The toolbar wraps (.form__inline): search takes the full width first, filter chips wrap below it. The bulk bar wraps its buttons onto a second line rather than hiding them in a menu.
  • Pagination wraps; below 640px show Previous, the current page and Next, with "Page 2 of 5" text.
  • The combobox popup is bounded by the visual viewport (min(24rem, 60dvh)) and keeps its status row visible, so Load more and Retry are always reachable at 400% zoom.

Accessibility

Role and pattern

Native <table> with <caption>, <th scope> and aria-sort, following the APG Table pattern and the sortable table example. Use role="grid" only when cells themselves need arrow-key navigation; Tessera tables do not. The paged picker follows the APG Combobox pattern with a multi-select listbox. Lists are <ul>.

Keyboard

KeyAction
Tab / Shift+TabToolbar, bulk actions, header checkbox, sort buttons, then each row's checkbox and action button, then pagination.
SpaceToggles the focused checkbox or filter chip.
EnterActivates a sort button (ascending, then descending), a page button or a row action.
↑ / ↓In the combobox list: move the active result without wrapping. ↓ on the last result requests the next page.
Page Down / Page UpIn the combobox list: move by the number of fully visible results. Page Down on the last result requests the next page.
Enter in the comboboxToggles the active result; with no active result, retries an error or loads more.

Focus

Sorting, filtering and selecting never move focus. Load more keeps the active result and the scroll position; appended results come after it. After a bulk action removes rows, focus moves to the bulk bar's count or, if the bar closes, to the table caption region. Changing page moves focus to the table region so the new rows are read from the top.

Labelling

Every table has a caption (visible or .visually-hidden) that includes the sort. Checkboxes name their row ("Select Ada Lovelace"); icon buttons name their row ("More actions for Ada Lovelace"). Counts go to one polite role="status" region: "4 of 48 learners match.", "6 more results loaded.", "2 learners selected."

Motion

Rows appear without animation. Skeletons shimmer over --duration-loop-shimmer and hold still under reduced motion; spinners slow to 2 s per revolution. Do not animate row reordering after a sort.

Touch

Row checkboxes and icon buttons sit in 32px controls inside rows that are at least 44px tall, with 8px between neighbours. Filter chips and pagination buttons are 44px. Do not rely on swipe gestures for row actions; the action button is always visible.

Content

  • Column headers are one or two nouns in sentence case: "Name", "Status", "Progress", "Due". Units go in the header, not every cell ("Progress (%)" if the cells show bare numbers).
  • Counts use numerals and name the thing: "6 of 24 learners", "4 of 48 learners match.", "2 learners selected", "24 learners available".
  • Status is a word in a badge ("In progress", "Overdue", "Complete"), never colour alone.
  • Dates in tables use the short form "30 Oct 2026"; never ambiguous numerals like 10/30.
  • Paging: "Load more results", "Previous page", "Next page", "Page 2 of 5".
  • Empty and error rows follow the formulas on empty and error states: "No learners match these filters" with "Clear filters"; "Learners could not be loaded. Your selections are safe." with Retry.
