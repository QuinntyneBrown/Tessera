Pattern

Navigation and page structure

Every Tessera surface sits inside a host LMS page: a top bar, a page header, then content. The course player adds an outline beside the content. One structure, one skip link and one landmark map mean learners always know where they are and how to get back.

Overview

All three mocks share one shell: a skip link, a top bar owned by the host LMS, then a single <main> holding a page header and the content. The SCORM player adds a second column, the course outline, built from the stepper inside a <nav>.

  • Shell: top bar, page header (eyebrow, title, lead or status), content. One <h1> per page, owned by the host.
  • Course player: outline (nav, "Course outline") and content (section named by the current activity heading), with Previous and Next below the content.
  • Wayfinding: breadcrumbs for hierarchy, tabs for views of one object, sub-pages for separate tasks.

Back behaviour

  • The browser Back button always works: every tab, sub-page and course activity that a learner would want to return to has a URL.
  • An in-page "Back to Workplace safety essentials" link goes to the parent, not to browser history; it is the same target as the last breadcrumb link.
  • Leaving the course player with unsaved progress never silently discards it: "Exit course" first shows the save failure with "Retry save" and "Exit without saving" (see dialogs and overlays).
  • Changing an activity, tab or sub-page moves focus to the new heading, never to <body>.

  • Current is never colour alone: the outline item adds a 4px stripe and aria-current="step"; the top bar link adds an underline and aria-current="page".
  • Locked activities stay focusable with aria-disabled="true" and their reason as the visible detail ("Locked until “Give useful feedback” is complete."), referenced by aria-describedby.
  • Loading and idle: while a course loads, the outline and content are replaced by a "Loading course" notice whose heading takes focus if focus was inside; after Cancel, "No course loaded" does the same.

Responsive behaviour

  • Top bar: below --layout-breakpoint-md (768px) the navigation collapses behind a menu button; the title and account stay visible. The bar wraps rather than scrolls.
  • Breadcrumb: .breadcrumb--collapse shows only the parent link ("‹ Workplace safety essentials") below 768px, which doubles as the back link.
  • Course player: below 768px the outline stacks above the content, collapsed behind "Show outline" (aria-expanded). Choosing an activity closes it and moves focus to the activity heading. Widening the window while the toggle had focus moves focus to the current outline item, never to <body>.
  • Tabs scroll horizontally inside the tab list only (never the page); at 200% text, tab labels stay on one line and the list scrolls.
  • Page header: title drops from --font-size-4xl to --font-size-3xl below 768px; actions wrap below the title.
  • At 320px and 400% zoom nothing scrolls horizontally except the tab list and data tables, which scroll inside their own wrappers.

Accessibility

Role and pattern

Landmarks per APG landmark regions; the outline toggle follows the disclosure pattern; breadcrumbs follow the breadcrumb pattern; tabs follow the tabs pattern with manual activation. The skip link satisfies 2.4.1 Bypass blocks.

Keyboard

KeyAction
Tab (first press)Reveals the skip link; Enter moves focus to main (or the player).
Tab / Shift+TabTop bar → breadcrumb → page actions → outline toggle → outline items → activity → Previous / Next. Outline items are each a Tab stop (a list of buttons, not a composite).
Enter, SpaceOpens an outline item, toggles the outline, follows a link.
← / →, Home / EndInside a tab list only: move between tabs; Enter or Space activates.
Alt+←Browser Back; returns to the previous URL, which restores the tab, sub-page or activity.

Focus

After an in-page navigation (activity change, tab sub-route, sub-page load) focus moves to the new heading (tabindex="-1"), so screen readers announce where the learner landed. A region that closes while it holds focus hands focus to the nearest visible heading. Focus is never left on <body>. The sticky top bar never covers the focused element (2.4.11): pages set scroll-padding-top to --layout-topbar-height.

Labelling

Each nav is named ("Main", "Breadcrumb", "Course outline"). The activity section is named by its heading; the iframe title repeats it ("Course content: Ask better questions"). Outline items use the title as the name and the status detail as the description. The page <title> changes with the view: "Ask better questions · Better conversations at work".

Motion

Smooth scrolling to anchors and the outline's open/close only run when prefers-reduced-motion allows; otherwise they jump. No navigation change animates the page content.

Touch

Outline items, tabs, top bar links and the outline toggle are at least 44px tall. Breadcrumb links meet the 24px minimum with 4px separators between them; on phones the collapsed breadcrumb leaves one larger target.

Content

  • Page titles name the object or task: "Assign learners", "Better conversations at work". Not "Dashboard page" or "Welcome".
  • Skip links name the destination: "Skip to player", "Skip to content".
  • Breadcrumb items use the page titles exactly; the current page is the last item and is not a link.
  • Tab labels are nouns in sentence case ("Learners", "Reports"); add a count only when it helps decide ("Learners 24").
  • Position text is explicit: "Activity 2 of 4". Locked reasons say what unlocks them: "Locked until “Give useful feedback” is complete."
  • Back links name the parent: "Back to Workplace safety essentials", never "Back" alone.
