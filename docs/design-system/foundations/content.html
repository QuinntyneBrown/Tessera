Content

Tessera's words appear in the middle of someone's learning: a lesson that will not load, a lecture that has dropped, a list of learners to assign. They should be plain, calm and about the learner, and they should sound the same in every component.

Overview

Every built-in string in the shipped packages can be replaced for localisation (VIDEO_PLAYER_I18N, the combobox strings). These rules apply to the English defaults and to any host that writes its own.

  • Say what happened, then what to do.
  • Use the learner's words: course, lesson, activity, learner, session. Not SCO, manifest, HLS or payload.
  • Short, but complete. A message a screen reader user hears once must make sense on its own.

Voice and tone

TraitMeansWriteNot
PlainEveryday words, short sentences, active voice. Readable at around a 9th-grade level."The video source stopped unexpectedly.""Media pipeline encountered a fatal decode exception."
CalmNo alarm, blame or exclamation marks. Reassure when work is safe."Your latest progress is kept on this page. Try saving again.""Error! Save failed!!"
Learner-firstTalk to the person ("you", "your"), about their task, not about the system."You don't have access to this stream. Sign in again or ask the organiser.""401 Unauthorized."
HonestSay what is known. Do not promise what the component cannot guarantee."Completion: Unknown""Completed" before the course reports it

Tone shifts with the moment, the voice does not. Routine status is brief ("Paused."); a problem is direct and gives a way out; success is quiet ("Progress saved.") and never celebratory inside a lesson.

Capitalisation and punctuation

  • Sentence case everywhere: headings, buttons, labels, menu items, tabs. "Course outline", "Clear all selections", "Exit course". Capitalise only the first word and proper nouns ("Lecture hall A", "Ada Lovelace").
  • Uppercase is styling, not text. The LIVE badge and eyebrows are written "Live" in markup and uppercased with text-transform, so screen readers do not spell them out. The video player's liveBadge string is the visible exception and is hidden from assistive technology.
  • Full stops end sentences in messages, hints and announcements ("Buffering."). Labels, buttons, headings and list items have none.
  • Contractions are fine and sound calmer: "couldn't", "don't", "can't". Use them consistently in one string set.
  • Ellipsis (the single character "…") marks work in progress: "Connecting…", "Loading learners…", "Reconnecting… attempt 2 of 5". It never marks a button that opens a dialog.
  • Quotation marks are curly and wrap names the learner typed or chose: No learners match “ad”.
  • No "please", no "sorry" in routine messages; once, if the failure is ours and blocks the learner, "sorry" is acceptable.

Button verbs

A button label is a verb, or a verb and its object, in sentence case. It says what happens, not what the control is.

One primary per view; labels stay under three words where possible.
  • Name the object when context does not: "Retry save", "Remove Ada Lovelace", "Clear all selections" rather than "Retry", "Remove", "Clear" when there could be doubt.
  • Keep the verb across a flow: if the button says "Exit course", the confirmation title is "Exit course?" and the announcement is "Course exited."
  • Destructive labels name the loss: "Exit without saving", "Remove 3 learners". Never "OK" or "Confirm".
  • Toggles keep one name and expose state with aria-pressed ("Captions", "Mute"); the video Play/Pause button names the action it will take.
  • Banned: "Click here", "Submit", "OK", "Yes"/"No" without context, "Learn more" with no object.

Error messages

Formula: what happened + how to fix it. Add what is safe when the learner might worry about losing work. Give the fix as a button when the component can do it.

Your latest progress is kept on this page. Try saving again.

  • Error titles are short noun phrases ("Progress not saved", "Connection lost"); the body is sentences.
  • Field errors sit next to the field, start with the fix, and do not repeat the label.

Announcements

Live-region messages are heard once, without the screen around them, often while the learner is doing something else. The combobox and video player each own one polite live region; errors use role="alert".

Rules

  • Complete sentences, ending in a full stop: "Captions on.", "Back live.", "All selections cleared." The full stop gives screen readers a natural pause.
  • Result first, then detail: "Ada Lovelace selected. 3 selected in total."
  • Announce changes, not states the learner caused and can see unless the change is otherwise silent: toggles are announced ("Muted.") because the icon change is not.
  • Coalesce: search messages within 150 ms collapse to the latest; selection and toggle messages queue in order and are never dropped. The SCORM player joins messages from one task into one announcement so a later one never overwrites an earlier one unread.
  • Wait before announcing slow work: "Loading results." only after one second; "Buffering." only after one second of stall.
  • Never announce every-second changes (the elapsed timer), decorative changes, or text that also receives focus (a dialog heading that takes focus is read anyway).
  • Errors go to role="alert" once, and a closed alert is cleared so it does not replay when the region reopens.
  • Polite by default. Assertive only for errors that block the task.

Usage

Drift between the mocks and packages to resolve when strings are next edited: the combobox writes "could not" where the video player writes "couldn't"; the system uses contractions.

Accessibility

  • Accessible names match visible labels and start with the visible text (WCAG 2.5.3): the LIVE badge is named "Live", or "Go to live, 12 seconds behind".
  • Errors identify and suggest (3.3.1, 3.3.3) and are linked to their field with aria-describedby.
  • Status messages use live regions (4.1.3) with the wording rules above.
  • Unavailable controls explain why in visible text referenced by aria-describedby: "Next is unavailable: locked until “Give useful feedback” is complete."
  • Link and button text stands alone (2.4.4): "Course outline", "Retry save".
  • Language: set lang on the page and on any phrase in another language; localised string sets keep the same sentence structure rules.

Tokens

Content owns no tokens. Text styles come from typography (--text-*); uppercase eyebrows use --letter-spacing-wide.
