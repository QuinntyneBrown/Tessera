Layout

Pages are built mobile first on a 4, 8 and 12-column grid inside a 1440px container. Content-driven wrapping, not breakpoints, decides when the course outline moves above the player, so layouts hold at 320px, at 400% zoom and with 200% text.

Overview

Tessera components live inside a host LMS, so they never assume the full viewport. Three rules follow from that:

  • Mobile first, min-width up. Base styles are the 320px layout; @media (min-width: …) adds columns. The mocks' max-width: 47.5em queries were rewritten this way.
  • Wrap on content, not on viewport where a component may sit in a narrow host column: the SCORM outline and the video notes use flex-wrap with a minimum basis instead of a breakpoint.
  • Grid tokens change at breakpoints for you. --layout-columns, --layout-gutter and --layout-margin are redefined in tokens.css at 48rem and 64rem, so a component reads the token and never writes its own media query for spacing.

Breakpoints

Five breakpoints in rem, so they move with browser text size. Custom properties cannot be used inside a media query, so write the rem value and name the token in a comment: @media (min-width: 48rem) /* --layout-breakpoint-md */.

Container and measure

  • Container: .container caps content at --layout-container-max (90rem, 1440px, the SCORM and video shells) and centres it, with --layout-margin as inline padding.
  • Measure: reading text caps at --layout-measure (60ch, the video mock's intro). Lead paragraphs, alert bodies, error-page and empty-state text use it; forms cap at 40rem; data tables and the player use the full container.

This paragraph sits in a container and stops at the 60-character measure even when the container is wider, so a learner's eye never travels too far to find the next line.

The wrapping-sidebar rule

From the SCORM mock: the course outline and the player share one flex row that wraps. The outline has a basis of 15.5rem and grows a little; the player has a basis of 30rem and grows 999 times faster. When the row cannot give the player 30rem, the outline wraps above it and both go full width.

.sidebar-layout { display: flex; flex-wrap: wrap; align-items: flex-start; gap: var(--layout-gutter); }
.sidebar-layout > :first-child { flex: 1 1 15.5rem; min-width: 0; }   /* outline */
.sidebar-layout > :last-child  { flex: 999 1 30rem; min-width: 0; }  /* player  */
  • Why not a breakpoint? The player may sit in a narrow LMS column on a wide screen, and enlarged text makes 30rem physically wider. A viewport query gets both cases wrong; wrapping gets both right.
  • Order: the outline comes first in the DOM and in reading order, so when stacked it is above the player, and below 768px it collapses behind an "Outline" toggle.
  • The same rule places the video mock's notes beside the session card (card basis 30rem, notes 16rem; there the main region comes first).

Usage

  • Wrap every page in .container; never set a page width yourself.
  • Use .grid for page regions, .grid--auto for card collections, .sidebar-layout for a side panel beside main content, and .stack / .cluster inside components.
  • Write media queries mobile first with min-width and the token's rem value. Prefer content-based wrapping (flex basis, auto-fill, container size) when a component may be placed in a narrow column.
  • Heights are minimums. The top bar, the player bar and the notice all grow with their content.
  • The SCORM frame keeps a fixed height (--content-player-height, 28.75rem from the mock) because the package inside scrolls itself; everything around it reflows.

Accessibility

  • Reflow (WCAG 1.4.10): every template works at 320 CSS px and at 400% zoom with no horizontal scrolling. Only data tables scroll sideways, inside their own region.
  • Text resize and spacing (1.4.4, 1.4.12): breakpoints and bases are in rem, and the wrapping sidebar reacts to text size, so 200% text never squeezes the player.
  • Order: visual order follows DOM order at every width; no order or row-reverse on content (the form-action reversal on phones puts the primary first, which is also its reading order there).
  • Landmarks: one header (top bar), nav for the outline and settings sections, one main, and aside for notes, each labelled when there is more than one of a kind.
  • Skip link: every page starts with a skip link to main, as in all three mocks.
