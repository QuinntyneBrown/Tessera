Foundation

Elevation

Tessera is mostly flat: cards and panels sit on the canvas with a hairline edge, not a shadow. Shadows are kept for things that float above the page, such as the learner popup, menus, toasts and dialogs, and a fixed z-order decides what covers what.

Overview

Depth has three tools, used in this order of preference:

  1. Surface colour: canvas, surface, raised and sunken backgrounds. Enough for cards, panels and wells.
  2. Borders: a 1px --color-border-default edge separates a card from the canvas in both themes and in forced colours, where shadows disappear.
  3. Shadows: only for layers that overlap content or respond to hover. The mocks used exactly one real elevation shadow, the combobox popup; everything else here is derived to give the system a complete, small scale.

--shadow-color is a bare RGB triplet (black) that every level reads through rgb(var(--shadow-color) / alpha), so a theme can tint all shadows at once without touching the levels.

Surface hierarchy

canvas < surface < raised, with sunken below surface. In light, surface and raised are both white and the shadow does the work; in dark, raised is a lighter sage so depth still reads where shadows barely show.

Z-order

Nine named layers with room between them. A component never writes a raw z-index; it picks a layer. Within one layer, later DOM order wins.

TokenValueShadowWhat lives here
--z-basenonePage content
--z-raisednoneStretched card links, the control bar over the video picture, a focused item lifted above its siblings
--z-stickynoneSticky top bar, sticky table headers, sticky dialog footer
--z-dropdown--shadow-3Combobox popup, menus, select lists
--z-overlaynoneDialog backdrop, drawer scrim
--z-modal--shadow-4Dialogs, bottom sheets, navigation drawer
--z-popover--shadow-3Menus and popups opened from inside a dialog
--z-toast--shadow-3Toast region; stays visible over a dialog
--z-tooltip--shadow-2Tooltips, skip link: always on top

The video player's fullscreen mode uses the browser's top layer, above every token. Native <dialog> opened with showModal() also uses the top layer; --z-modal covers non-native fallbacks.

Dark theme elevation

Shadows are nearly invisible on a dark canvas, so the dark theme does two things: it raises alpha on every level (0.4 to 0.6 instead of 0.1 to 0.2), and raised surfaces become lighter (sage-850 over sage-900 surface over sage-950 canvas). Light comes from above in both themes: higher means lighter.

Usage

  • Cards, panels and the players sit on the canvas with a border and no shadow. Add --shadow-2 only on hover of an interactive card.
  • Pair elevation and layer: a popup is raised surface, --shadow-3 and --z-dropdown together. Do not mix a modal shadow with a dropdown layer.
  • Never use shadow as the only edge of a control; a control's edge is --color-border-strong.
  • Do not stack shadows on nested elements; only the outermost floating layer casts one.
  • New layers are new tokens. If a component needs to sit between two layers, discuss it; do not write z-index: 1001.

Accessibility

  • Forced colours: shadows are removed in Windows High Contrast, so dialogs, menus and the combobox popup also carry a 1px border, which forced colours maps to a system colour. Tooltips use the inverse surface, which forced colours replaces with Canvas and CanvasText.
  • Focus not obscured (WCAG 2.4.11): sticky layers (--z-sticky) are short, and pages with a sticky top bar set scroll-padding-top to the top bar height so a focused element is never hidden beneath it. Toasts sit in a corner, away from the focused control.
  • Meaning: elevation is never the only cue that something is modal; dialogs also trap focus, set aria-modal and dim the page with --color-bg-backdrop.
