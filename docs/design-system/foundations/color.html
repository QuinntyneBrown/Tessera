Foundation

Color

Sage-tinted neutrals carry the interface, one teal accent marks what matters, and an amber ring shows where the keyboard is. Every colour a component uses is a semantic token with a value in each theme, and every pairing is checked against WCAG 2.2 AA.

Overview

Colour has two tiers. Primitives (--palette-*) are raw values on five ramps; only semantic tokens read them. Semantic tokens (--color-*) name a job: --color-bg-surface, --color-fg-muted, --color-border-strong. Components and pages use semantic tokens only, and a theme changes only semantic tokens.

  • Neutrals are sage, not grey: the mocks' ink #18312e, muted #536763 and canvas #f4f7f5 all lean green, which keeps the teal accent calm against them.
  • One accent. Teal means "act here" or "you are here": primary buttons, the current lesson, selected learners, links.
  • Focus is amber. It never shares a hue with selection, so a focused, selected chip still shows both.
  • Status is never colour alone. Notices pair a hue with an icon, a title and a 4px stripe.
  • Media is its own set. Controls over video sit on a dark scrim in both themes, so they get their own tokens.

Primitive ramps

Steps run from 25 (lightest) to 975 (darkest). Gaps in a ramp are intentional: only steps a semantic token uses exist. Never use a primitive in a component or a page; if you need a colour that has no semantic token, that is a missing role, not a reason to reach for --palette-*.

Sage

Green-tinted neutrals: ink, lines, canvas and every dark-theme surface. 13 steps because both themes are built from it.

Teal

Brand and accent. 600 is the light accent (the mocks' --accent); 300 is the dark accent and the media accent.

Orange

Focus ring (600 light, 300 dark and on media) and warning.

Red

Errors and destructive actions; 300 is the LIVE dot on media.

Blue

Information only. No mock uses blue; derived so info never reads as brand.

Anchors

Swatches follow the page theme; switch it with the theme toggle or the t key. Values are read live from tokens.css.

Both themes

Dark is built from the roles, not by inverting light. Surfaces get lighter as they rise (canvas < surface < raised), the accent lightens to teal-300 and text on it flips to sage-900, and status fills become deep tints with light text. Light is :root; dark applies with [data-theme="dark"] or the OS preference unless a page forces [data-theme="light"]. See theming.

Usage

  • Pick by job, not by look: text is --color-fg-*, fills are --color-bg-*, edges are --color-border-*. A fill token used as text is not checked for contrast.
  • Every control edge (input, secondary button, checkbox, chip) is --color-border-strong. --color-border-default is for dividers and card edges only.
  • Hover backgrounds are --color-bg-subtle (rows, secondary buttons) and --color-accent-hover (primary). Selected rows and the current lesson are --color-accent-subtle plus a 4px --color-accent stripe.
  • Disabled text stays --color-fg-disabled, which passes 4.5:1; the dashed edge says "disabled". Never lower opacity to disable a control outside the media bar.
  • Use --color-fg-on-accent on accent fills and --color-fg-on-danger on danger fills; both flip to dark in the dark theme.
  • Inside the video player use --color-media-* only; page tokens are not checked against the scrim.
  • Under prefers-contrast: more default borders and muted text are raised to their strong counterparts; under forced-colors: active the focus ring, borders and media accents hand over to system colours.

Adding a brand theme

An LMS host that needs its own accent adds primitives for its hue and a theme block that overrides semantic tokens only. Components never change.

  1. Add the brand ramp to the primitives in tokens.css (for example --palette-plum-50 to --palette-plum-800), keeping the step numbers' meaning: 600 passes 4.5:1 on white, 300 passes 4.5:1 on sage-900.
  2. Add a [data-theme="plum"] block (and [data-theme="plum-dark"]) that remaps --color-accent*, --color-fg-link*, --color-fg-accent and, if needed, --color-fg-on-accent. Leave the focus ring amber unless the brand hue is itself orange.
  3. Add every pair that changed to contrast-pairs.json with the new theme name and run the contrast check; adjust primitives until each pair passes with margin (4.8:1 for text, 3.3:1 for edges).
  4. Re-export tokens.json and map the new accent onto @tessera/theme (--t-colorBrandBackground, --t-colorBrandForeground1).
[data-theme="plum"] {
  --color-accent: var(--palette-plum-600);
  --color-accent-hover: var(--palette-plum-700);
  --color-accent-active: var(--palette-plum-800);
  --color-accent-subtle: var(--palette-plum-50);
  --color-accent-subtle-hover: var(--palette-plum-100);
  --color-fg-accent: var(--palette-plum-600);
  --color-fg-link: var(--palette-plum-600);
  --color-fg-link-hover: var(--palette-plum-700);
}

Accessibility

Every pair below is listed in tokens/contrast-pairs.json and is computed live in both themes. Text needs 4.5:1 (WCAG 1.4.3); control edges, icons and focus indicators need 3:1 (WCAG 1.4.11). The info border is listed at 1:1 because it is decorative: the fill, icon and title carry the meaning. Pairs with a translucent background (scrim, caption) are composited over white here, the worst case for light text; over the black picture they score higher. Two badge pairs differ per theme, so they appear in one column only.
