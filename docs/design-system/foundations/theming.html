Foundation

Theming

A theme is a set of values for the semantic tokens, nothing more. Light and dark ship with the system; an LMS can add its own brand theme, and the shipped Angular packages read the same decisions through @tessera/theme.

Overview

Components never read a raw value. They read a semantic token such as --color-accent (directly or through a component token such as --btn-bg), and a theme decides what that token is. Switching theme therefore changes every component at once and cannot leave one behind.

How themes work

  • Light is the default and lives on :root.
  • Dark applies when an element (usually <html>) has data-theme="dark", or when the operating system prefers dark (prefers-color-scheme: dark) and the page has not forced data-theme="light". tokens.css repeats the dark block in both places, and the two copies stay identical.
  • Scoped themes: data-theme works on any element, so a dark video panel can sit on a light page. Everything inside inherits it.
  • color-scheme is set by each theme (light or dark), so native scrollbars, form controls and the SCORM content frame's default canvas follow the theme.
  • Persisting a choice: an LMS that offers a theme switch writes data-theme on <html> before first paint and stores the choice; "System" removes the attribute.
<html lang="en" data-theme="dark">           <!-- force dark -->
<html lang="en">                             <!-- follow the OS -->
<section class="media-player" data-theme="dark">…</section>  <!-- scoped -->

Dark is not inverted light. Surfaces get lighter as they rise (canvas, then surface, then raised), the teal accent lightens to --palette-teal-300, text on the accent flips to dark ink, and status backgrounds become deep tints with light text. See colour for every value and contrast pair.

Token tiers

TierPrefixExampleWho reads itWho changes it
1. Primitive--palette-*, --font-*--palette-teal-600Semantic tokens onlyThe design system, rarely
2. Semantic--color-*, --text-*, --space-*, --radius-*, --shadow-*, --duration-*, --ease-*, --z-*, --layout-*, --target-*, --control-height-*--color-accent: var(--palette-teal-600)Components and pagesThemes
3. Component--btn-*, --field-*, --combobox-*, --media-*, --alert-*…--btn-bg: var(--color-accent)One componentA host re-skinning one component

A theme overrides tier 2. A host that wants one component to look different overrides tier 3 on a container. Nobody overrides tier 1 from outside the system, and no component reads tier 1 directly.

Adding a theme

  1. Add a block [data-theme="<name>"] to your own stylesheet, after tokens.css.
  2. Override semantic tokens only, mapping each to a primitive or to a new primitive you add beside it.
  3. Set color-scheme.
  4. Check every pair in tokens/contrast-pairs.json in the new theme: 4.5:1 for text, 3:1 for control edges, icons and the focus ring.
  5. Check forced colours and reduced motion still behave; your theme should not touch those blocks.

CSS
[data-theme="northwind"] {
  --color-accent: var(--palette-blue-600);
  --color-accent-hover: var(--palette-blue-800);
  --color-accent-active: var(--palette-blue-800);
  --color-accent-subtle: var(--palette-blue-50);
  --color-fg-accent: var(--palette-blue-800);
  --color-fg-link: var(--palette-blue-800);
  color-scheme: light;
}

A brand theme that also needs a dark variant writes [data-theme="northwind-dark"] with its own values; it does not try to derive them from the light ones. In the shipped packages the same customer theme is createTheme({ colorBrandBackground: …, colorBrandForeground1: … }) applied with applyTheme(container, theme).

Contrast and forced colours

prefers-contrast: more

Decorative borders (--color-border-default) take the strong border value, and muted and subtle text (--color-fg-muted, --color-fg-subtle) take the default text colour. Hierarchy then comes from size and weight alone.

forced-colors: active

Windows contrast themes replace author colours with system colours. tokens.css hands the focus ring and media focus ring to Highlight, borders to CanvasText and ButtonText, the media scrim to Canvas, and the media accent and LIVE dot to Highlight. components.css adds a 1px ButtonText border to buttons, chips, badges, media controls, toasts and tooltips (whose shape otherwise came from a background), and marks selected options, the current lesson and the current page with Highlight. The shipped combobox does the same through its --t-combobox-* properties.

prefers-reduced-motion: reduce

Durations drop to near zero in the tokens; the spinner slows to 2 s. See motion.

Consuming tokens.json

tokens/tokens.json is a Design Tokens Community Group (DTCG) export of tokens.css, for platforms that cannot read CSS (native apps, e-mail templates, a design tool plug-in). tokens.css stays the source of truth; regenerate the JSON when it changes.

  • Groups follow the CSS names: color.accent is --color-accent, space.4 is --space-4.
  • Each token has $type and $value. Semantic values are aliases such as {palette.teal.600}.
  • $extensions["com.agent-toolkit"] carries the CSS name, the resolved light value and per-theme overrides under themes.dark.
"accent": {
  "$type": "color",
  "$value": "{palette.teal.600}",
  "$extensions": { "com.agent-toolkit": {
    "css": "--color-accent",
    "themes": { "dark": { "$value": "{palette.teal.300}" } }
  } }
}
// Read the dark value of a token, falling back to light.
const tokens = await (await fetch('tokens/tokens.json')).json();
const accent = tokens.color.accent;
const dark = accent.$extensions['com.agent-toolkit'].themes?.dark?.$value ?? accent.$value;

The SCORM player has no component-specific properties; it reads the shared --t-* tokens directly. Course content inside its frame keeps its own styles and is never themed.

Usage

  • Theme with semantic tokens; re-skin one component with its component tokens; never edit components.css to change a colour.
  • Put data-theme on the highest element that should change. Do not toggle classes on individual components.
  • Never hard-code a colour in a component, even one that "never changes"; forced colours and future themes both need it to be a token.
  • A custom theme is the host's accessibility responsibility (as the @tessera/theme README says): keep 4.5:1 text, 3:1 controls and focus, 44px targets and a visible focus ring.

Accessibility

Every theme must pass the same pairs. These are checked live for the current theme:

Body text on surface
Muted text on canvas
Label on accent
Control edge on surface
Focus ring on canvas

Switch the page theme with the toggle in the navigation (or press t) to check the other theme. The full list lives in colour and in tokens/contrast-pairs.json.

Tokens

Theming owns no tokens: it changes the values of the semantic tokens documented on colour, typography, spacing, shape, elevation and motion. The tokens a theme normally overrides are the --color-* group, --shadow-* (dark shadows are deeper) and color-scheme.
