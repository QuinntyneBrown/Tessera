Foundation

Responsive

Learners open courses on phones between shifts, on shared lab laptops and on wall screens in a lecture hall. Every Tessera component works at every width from 320 CSS px up, at 400% zoom, with text doubled and with spacing overrides applied, without horizontal scrolling or lost content.

WCAG 1.4.4, 1.4.10, 1.4.12Mobile firstNo tokens owned

Overview

  • Mobile first. Base styles are the phone layout. Wider screens add columns, side navigation and space; they never fix a broken narrow layout.
  • Content decides, not devices. Prefer layouts that wrap on their own (flex-wrap, auto-fill grids, the wrapping sidebar layout) over media queries. Use a breakpoint only when the arrangement has to change.
  • Everything in rem. Sizes and breakpoints are in rem, so a learner who sets a larger default font gets the narrow layout sooner, exactly as if the screen were smaller.
  • Nothing is removed. A control can move into a menu or below the picture, but every action available on a desktop is available on a phone.

The SCORM player layout below wraps without a media query: the outline sits beside the lesson while the lesson can keep 30rem, and stacks above it otherwise. Drag the corner of the frame to try it.

The mocks wrote breakpoints as max-width: 40em and max-width: 47.5em. The system normalises them to 40rem and 48rem written mobile first. Where a "below" rule is clearer, use max-width: 47.99rem so it never overlaps the min-width: 48rem rule.

Touch and pointer

  • Hover is an enhancement. Every hover style in components.css sits inside @media (hover: hover), so a tap never leaves a "stuck" hover colour on a phone. Nothing is reachable only by hover: the combobox's full-label tooltip also opens on focus of the chip's remove button, and the video control bar reappears on tap and on focus.
  • 44px by default. Buttons, fields, media controls and toggles are 44px (--target-comfortable, --control-height-md), so on a coarse pointer every primary target already meets 44 × 44px and no (pointer: coarse) enlargement is needed.
  • Smaller targets are the exception: 32px (--control-height-sm) chips and the 28px chip remove button keep at least 24px (--target-min, WCAG 2.5.8) and sit in rows where they are not crowded by other targets. If a product adds a (pointer: coarse) rule, it may only grow targets toward 44px, never shrink them.
  • No gesture-only actions. Swipe, pinch and long-press are never the only way; the volume slider has Mute and arrow keys; anything dragged has a button alternative (WCAG 2.5.7).
  • Safe areas. Fixed bottom elements (toasts, sheet footers) add env(safe-area-inset-bottom); full-height layouts use 100dvh so mobile browser chrome does not clip them.
  • On-screen keyboards must not cover the focused field: the combobox keeps the input in view when its popup opens.

Zoom, text and spacing

These are project requirements in AGENTS.md, not aspirations. Each one is checked on every component change.

ConditionRequirementHow the system meets it
320 CSS px wideEvery component fully works with no horizontal page scroll (WCAG 1.4.10 Reflow).minmax(0, 1fr) grids, min-width: 0 on flex children, wrapping rows, min(…, 100%) in every auto-fill grid.
400% browser zoomAt 1280px wide, 400% zoom gives a 320 × 256 CSS px viewport. Everything stays operable; short heights matter as much as narrow widths.Popups cap their height with dvh; the combobox anchors to its input row; sticky elements stay small; the video control bar moves out of the picture.
Text enlarged to 200%Text-only enlargement (root font size 200%) loses no content or function (WCAG 1.4.4).Sizes in rem/em; heights are min-height, never fixed; labels wrap rather than truncate (long chip labels ellipsise but keep their full name and a tooltip).
Text-spacing overridesLine height 1.5×, paragraph spacing 2×, letter spacing 0.12em, word spacing 0.16em lose nothing (WCAG 1.4.12).No fixed-height text containers; no overflow: hidden on text except deliberate, tooltipped ellipses.
OrientationPortrait and landscape both work (WCAG 1.3.4).No orientation lock; fullscreen video does not force landscape.

Data tables and the video picture are the only things allowed to scroll in two dimensions, and they do it inside their own frame.

Usage

  • Never set a fixed height on anything containing text; use min-height.
  • Never hide content at a breakpoint unless the same content or action is reachable another way.
  • Keep the DOM order the same at every width; only the visual arrangement changes, so reading and focus order stay logical (WCAG 1.3.2, 2.4.3).

Accessibility

  • Reflow (1.4.10): 320 CSS px with no two-dimensional scrolling except tables and the video picture.
  • Resize text (1.4.4): 200% with no loss.
  • Text spacing (1.4.12): overrides lose nothing.
  • Target size (2.5.8): at least 24px everywhere, 44px by default.
  • Focus not obscured (2.4.11): sticky headers, toasts and the video control bar never cover the focused element; documentation pages use scroll-padding-top.
  • Consistent order (1.3.2): breakpoints rearrange, never reorder, content.

See accessibility for the full commitment list.

Tokens

Responsive owns no tokens. Breakpoints, columns, gutters, margins and container widths (--layout-*) are on layout; target sizes and control heights (--target-*, --control-height-*) are on accessibility.
