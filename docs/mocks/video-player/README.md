# Video player HTML mock

Open [index.html](index.html) directly in Chrome. It needs no build, server, network, or account. The picture is a fictional lecture hall scene drawn on a canvas in the page; the session, presenter, and captions are invented, and nothing is streamed, recorded, or sent anywhere.

This is a design artifact for [the video player requirements](../../specs/L2.md) (L2-057 to L2-094) and the transport decision in [ADR-0002](../../adr/frontend/0002-stream-live-video-as-fmp4-over-signalr-messagepack.md). It simulates connecting, live playback, buffering, pause and resume-to-live, reconnecting (recovering and giving up), the ended state, the unsupported-codec and unauthorized errors, blocked autoplay, captions on and off, a slow network, and the light, dark, and system themes. It does not implement SignalR, MessagePack, Media Source Extensions, fragmented MP4, Angular, the injectable transport, the i18n token, the consumer harness, or the production reconnect timing. The generated stream has no audio track, so mute and volume change only the controls' state. Component colors use the design's `--t-video-player-*` token names with their light and dark defaults; host-page colors use separate `--page-*` variables.

The Scenario selector exposes every state above. Switching scenarios resets local state. The Theme selector shows the light or dark tokens, or follows the system preference. Reset restores the default: the Live scenario, light theme, volume 60, captions off. The mock connects in 2 s (8 s for the slow scenario, with "Still connecting…" at 5 s), stalls for 2.5 s in the Buffering scenario, announces buffering only after 1 s, hides the control bar 3 s after the pointer rests, and shows the "Back live" toast for 1.5 s. Reconnect delays are compressed to 0, 1, 2, 3, 3 s; the production schedule in L2-067 is 0, 2, 5, 10, 10 s.

Keyboard interaction:

- Tab order is Play/Pause, Mute, Volume, LIVE, Captions, Fullscreen. The stage itself is not in the Tab sequence.
- Space or K pauses and resumes from anywhere inside the player except the volume slider; Space on a focused button is that button's own activation. Resume jumps to the live edge and announces "Back live."
- M toggles mute. Arrow Up and Arrow Down change the volume by 5 from anywhere inside the player; on the slider itself the native arrow behavior applies and the player does not apply a second change. Volume 0 shows the muted icon.
- C toggles captions. F toggles fullscreen; Escape leaves it. Ctrl, Alt, and Meta combinations are ignored.
- Clicking or tapping the stage toggles playback. On touch, the first tap on hidden controls only reveals them; the next tap toggles.
- The LIVE badge is a button that is `aria-disabled` at the live edge and becomes "Go to live, n seconds behind" when playback falls behind; Enter or Space on it jumps to live.
- Retry in an error panel is an ordinary button; after Retry, focus moves to Play.

Accessibility structure: the player is a `role="region"` named "Video player: Lecture hall A". The control bar is `role="group"` named "Player controls" (not `toolbar`, because arrow keys are reserved for volume), with native buttons, `aria-pressed` on mute, captions, and fullscreen, `aria-disabled` on controls that stay focusable while unavailable, and a native range input with `aria-valuetext`. The elapsed time is `aria-hidden` because it changes every second; milestones are reported through a polite live region inside the component that coalesces status messages within 150 ms and never drops a toggle announcement. Errors use a `role="alert"` panel whose heading takes focus when focus was inside the player; the unsupported error has no Retry. Captions are a real `<track kind="captions">` built from a blob URL, styled with `::cue`, and positioned above the control bar while it is visible. Hidden controls use a class, never `aria-hidden`, so focus still reaches and reveals them. Below 47.5em the control bar sits below the picture instead of over it and does not hide. The LIVE dot pulses and the controls fade only when `prefers-reduced-motion` allows; forced-colors mode maps the scrim, controls, and dot to system colors.

One-off Chromium inspection and axe checks are design review evidence, not a production acceptance suite: axe reported zero violations scoped to the player in the connecting, live, paused, buffering, reconnecting, ended, unsupported, unauthorized, autoplay-blocked, dark, forced-colors, and 320 by 256 CSS px states. No tests are added for this mock, as required by AGENTS.md. A 320 by 256 CSS px viewport checks reflow; it is not actual 400% browser zoom. Screen reader observations, real touch devices, real fullscreen behavior across browsers, and production accessibility and performance certification remain separate execution work.
