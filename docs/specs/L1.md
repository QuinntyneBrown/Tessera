# L1 - High-Level Requirements

## L1-001: Course loading
The player must accept either a SCORM ZIP package or an extracted course supplied by the host LMS, identify its version and course structure, and reject invalid or unsupported content with a clear explanation.

## L1-002: Course launch and navigation
The player must launch the course content selected by the learner and provide navigation that respects the course's structure and sequencing rules.

## L1-003: SCORM runtime compatibility
The player must provide the browser runtime communication required by SCORM 1.2 and SCORM 2004 2nd, 3rd, and 4th Editions, including their data models and error behavior.

## L1-004: Learner state and outcomes
The player must track and restore each learner's course state and report the course's progress, score, and completion outcomes accurately.

## L1-005: LMS integration
The player must exchange course state and outcomes with the host LMS through a documented integration boundary and report persistence failures.

## L1-006: Security and data protection
The player must protect learner data and the host application from untrusted course content, validate external input, and rely on the host LMS to establish learner identity and authorize course access.

## L1-007: Accessibility
The player controls and status information must conform to WCAG 2.2 AA, work by keyboard alone, and be usable with JAWS, NVDA, VoiceOver, TalkBack, and Narrator.

## L1-008: Responsive performance and reliability
The player must remain fully usable from extra-small to extra-large viewport sizes and at up to 400% browser zoom, meet defined performance targets, and present recoverable loading and failure states.

## L1-009: Combobox asynchronous search
The combobox must let a learner or administrator find options in a remote data set by typing, without loading the whole data set up front, and must show loading, empty, failure, and paged states without losing the user's place.

## L1-010: Combobox multi-selection
The combobox must let the user select and deselect many options from its results, show every selection as a removable chip, and recognise selected values regardless of whether they are in the current results.

## L1-011: Combobox popup behaviour
The combobox must open and close its results popup predictably, keep it attached to the field at the field's width, and never obscure or take focus from the field the user is typing in.

## L1-012: Combobox form-control integration
The combobox must behave as a first-class Angular form control, with value, disabled, touched, and validation behavior, and must also be usable without Angular forms.

## L1-013: Combobox keyboard operation
Every combobox function must be operable by keyboard alone, using the WAI-ARIA Authoring Practices input-focus conventions and a documented multi-select listbox extension, in both left-to-right and right-to-left layouts.

## L1-014: Combobox screen reader support
The combobox must expose its roles, states, selections, results, and changes to assistive technology so that JAWS, NVDA, VoiceOver, TalkBack, and Narrator users receive the same information as sighted users, with no accessibility work from the consuming application beyond supplying a label.

## L1-015: Combobox visual accessibility and responsiveness
The combobox must conform to WCAG 2.2 AA in its visual presentation and pointer and touch interaction, and must remain fully usable from extra-small to extra-large viewport widths, at up to 400% browser zoom, with enlarged text, and with WCAG text-spacing overrides.

## L1-016: Combobox customization, localisation, and public API
The combobox must offer a documented public interface that lets a consuming application supply its data source, labels, and localised strings and customise option, chip, and empty-state content without being able to break the accessibility pattern.

## L1-017: Combobox security, performance, and reliability
The combobox must treat data returned from the consumer's data source as untrusted when rendering, stay responsive while requests are in flight, contain data-source failures, work without zone-based change detection, and release every resource it acquires.

## L1-018: Combobox verification and documentation
The combobox must ship with the automated and manual accessibility verification, a consumer test harness, and the documentation needed to adopt it and to prove its behavior.

## L1-019: Shared design tokens and themes
Tessera components must share a typed, scoped theme API, retain accessible system defaults, and allow host visual customization.
